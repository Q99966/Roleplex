# 固定世界管理者与协作通信修复验收

日期：2026-09-23。范围为[身份、来源与任务广播修复 R1–R4](../plan/world-coordination-message-provenance-v1.md)。实际接口见[世界管理者](../protocol/public/rest/world-orchestrator.md)和[协作通信](../protocol/public/rest/workflow-communication.md)。

## 完成内容

- 每个 World 的 Owner 就绪后建立固定管理者和岗位会话；初始无模型时明确待配置。导入普通角色形成独立配置，普通角色及其私人会话保持不变；原绑定升级后沿用岗位历史。模型/人设编辑与启停保持管理身份，旧授权不复活。
- 真人要求、世界委派、群协调回复、系统派发和角色结果有准确主体/职责、接收对象及回复关系。客户端自称世界管理者或正文写 @ 不取得派发能力。
- 同批三角色只显示一条公开派发卡；并发槽位不足的角色显示等待，执行、结果、停止和用量仍各自独立。相反条件边不合并，手动判断节点保留收件人。v1 串行节点也不再伪造 Owner 执行输入消息。
- 完整目标/节点要求保存在原 execution 关联的 execution_inputs；公开群消息没有重复的内部提示。Owner 可从任务卡或节点详情核对完整输入；来源缺失的旧输入仍保留原文读取入口。
- 平台模板 v2 与 Context schema 10 增加通信规则和本次角色/报告关系，Owner 自定义覆盖保留。来源回填依据实际关系而非文字相似性；共享投影 v3 排除旧内部输入，旧污染摘要与 Memory 引用失效。
- 消息窗口在 communication_updated 后重新读取来源，保持仍可定位的锚点和人工草稿；新模式不改变原普通 @ 路由、根预算、循环/反馈处置或 World 隔离。

## 升级与覆盖边界

正常重启后端会执行迁移、专用身份初始化和来源回填。旧绑定的普通角色不被删除或改成系统角色；原岗位会话、旧字段、文字、调用和文件事实保留。已有三条历史节点输入可分别折叠回读，不按相同文本强行合并或删除。没有可靠关联时明确标记历史来源不完整。

本次不替用户正在使用的后端执行进程切换或真实模型任务。部署前按项目正常流程备份并停止旧服务，再使用配套前后端启动；旧换绑写入口已明确拒绝，需使用新的配置/导入/启停入口。含新身份/输入的数据无法无损降回旧语义时迁移拒绝，不静默丢弃来源。

环境为 WSL2/Linux、Python 3.12、Node 24、Chromium。PostgreSQL 只有离线 SQL，没有实例验证；未在 Windows 原生或移动设备实机验证。fake 结果证明机制和状态，不证明真实模型的故事、规划或摘要质量。截图/报告按现有保留策略管理，未公开发布，不替代用户验收。

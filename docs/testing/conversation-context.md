# 持久会话上下文与占用验收

日期：2026-09-22。范围为[总体计划](../plan/conversation-context-memory-capabilities-v1.md)的 B：单聊/群聊共享材料持久化、事务同步/恢复、按角色请求预览和调用级输入估算。协议与数据字段分别见[上下文协议](../protocol/public/rest/conversation-context.md)和[数据模型](../protocol/internal/data-model.md)。

## 验证内容

- 新建空会话立即有材料身份；消息和材料在同一事务提交/回滚；生成中的文本不重复改写投影，终态、停止标记及来源 revision 正确保存。
- 并发写入从同一旧版本开始，材料版本原子递增且来源不丢失。来源删除级联移除条目；分页使用材料版本，变更后拒绝继续拼接旧页。
- 旧消息分批回填，中断后保留已经提交的批次，恢复只补剩余部分；重启收口 pending，完整历史保持原样，错误/中断片段明确排除而不抹掉原消息。
- 同一角色的预览消息序列和实际 Provider 首次输入完全一致，首次估算相等。角色自身/其他发言的相对身份正确，同一 @ 链后序角色收到前序终态；执行开始后的来源修订不改写已经采用的快照。
- 裁剪前全量压力高于窗口时明确显示，预算内输入、被裁剪数量、固定规则/工具/本次消息/历史/中断事实组成分别可查。估算不补造厂商 usage。
- 真实工具链读取受控文件，第二次模型调用的输入包含工具参数及返回结果，估算随之增长；只保存数字摘要，不把原始工具输出写入来源快照。
- Owner/Guest、会话成员与角色范围、删除/恢复、在途预览撤权和下一次模型调用前撤权均覆盖。收回角色后不再派发模型，已提交文件和工具事实保留。
- 派生缓存的来源归属不能代替原消息归属；来源版本或归属失配时拒绝读取，不返回其他会话正文。
- 桌面/窄屏按需切换“占用与输入”“会话材料”“提示词”；草稿预估不发送消息，未保存提示词可返回，读取失败清除旧输入并可重试。原输入框、@、中文输入法和迟到响应路径继续正常。
- 物理测试 World 实际切换、重新认证、后端重启后材料保留，同 ID 的其他 World 不能混入来源。

## 覆盖边界

环境为 WSL2/Linux、Python 3.12、Node 24、Chromium、隔离 SQLite 和物理测试 World。全程使用确定性 fake Provider，没有收费模型调用；本地 UTF-8 保守估算不是模型 tokenizer 的精确结果。PostgreSQL 只验证离线 SQL，没有实例部署验证；未进行 Windows 原生、其他浏览器或移动设备实机验证。

本批提供未压缩的持久材料与版本来源，尚无主动/自动压缩、阈值策略、Memory 搜索或 Skills/MCP 产品模块。每次工具轮已记录输入增长，执行内压缩与相应容量处理按 D 实施。旧执行没有记录的输入估算保持未知；不会重建过去的完整 Prompt，或将新版角色窗口套在历史调用上。源消息仍由原 reducer 管理，新增编辑/再生成功能需接入同事务 revision/投影，本批没有顺带实现这些消息操作。

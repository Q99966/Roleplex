## 问题与范围

只读排查发现同响应 Shell 审批持工作区锁约 36.6 秒，批量写入在执行前等锁 5 秒失败。
同步屏障复现了预检释放锁→审批等待取得锁→批量提交前超时。纯排查按用户要求不单独提交。

本次 Shell 等待审批不持该锁，批准后重新取得锁并复核权限再执行；原运行实例配额和审批身份保持不变。
单项与批量 write/edit 共享独立准入、取消和累计等待预算，文件/目录提交证据保持原规则。
具体数值与错误语义只以[工作区等待契约](../protocol/public/rest/workspaces.md#原生修改的有界等待)及[Shell 审批](../protocol/public/messaging/shell-approvals.md)为准。

## 确定性验证

backend 下执行：

```bash
python -m pytest -q --tb=short --show-capture=no
```

最终全量：**374 passed、3 skipped、12 deselected，257.46 秒**。契约用例按普通回归配置排除。
新增专项 `test_write_admission.py` 与批量回归合计 **38 passed**，覆盖：

- 待审批 Shell 不阻塞同轮实际写入；批准后等待锁期间撤权/取消不启动进程，正常批准只执行一次。
- 实际工具工厂的单项和批量共享一个池；出队后重新授权，撤权/取消/超时不迟到落盘。
- 队列数量、参数字节、超时和关闭原因明确；锁等待累计预算不在下一次获取锁时重置。
- 关闭同时回收活跃/等待者；容量移交与取消竞争不泄漏槽位或排队字节。
- 旧文件版本、父目录凭据、批次部分成功、diff 降级、命令进程和服务保护沿用原回归。

新增测试最初暴露 fake 流式替身只发送同响应第一个工具调用，现按真实索引发送全部调用，普通模型用量仍不伪造。
一次扩展回归出现进程清理断言竞态：存在性检查后进程退出，读取状态抛 NoSuchProcess；已改为直接检查并接受确已退出，未放宽运行中进程的失败条件。
根目录启动的一次全量检查因未使用 backend/pytest.ini 主动中止，未作为验收结果；最终以上结果来自 backend 目录的标准配置。

## 边界与人工核对

人工可让同一轮同时请求 Shell 与文件写入，暂不批准 Shell，确认写入先完成；再批准/拒绝，确认调用状态准确。
写队列只减少执行前短暂争用，不自动重放已提交或未知操作；业务提交失败按原凭据处理。
后台服务启动/存续的原写保护保持不变；没有增加运行中编辑权限、全机沙箱或跨进程锁。
当前没有统一 Agent 墙钟截止，累计等待只计准入与锁等待；文件同步提交不因等待额度被中途取消，图步数不变。
没有修改文件大小限制、Token 统计、长期记忆或自动恢复，没有新增表或迁移。

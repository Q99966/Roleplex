# 自动压缩与运行边界验收

日期：2026-09-22 至 2026-09-23。范围为[总体计划](../plan/conversation-context-memory-capabilities-v1.md)的 D。配置、执行与迁移契约见[压缩协议](../protocol/public/rest/context-compression.md)、[Agent 运行时](../protocol/internal/agent-runtime.md)和[数据模型](../protocol/internal/data-model.md)。

## 完成范围

- 世界默认与会话覆盖、自动开关、Token 阈值/目标、建议预留、摘要模型、最近消息保留、自动提示词和冷却/新增材料门槛。主动压缩的一次性要求保持独立。
- 阈值上限取全部有效角色的最小窗口，推荐触发值为上限减建议预留。200k／1M／100k 得到上限 100k、默认推荐 50k；32k 窗口显示调整后的 16k 预留和 16k 推荐值。成员窗口变化重新计算，原配置与实际收紧值分别显示。
- 自动维护复用原 chain 预算并关联父 execution，为原任务保留至少一次后续决策。共享材料并发去重，失败/取消/无收益保留原文，相同输入不反复付费；队列内的手动维护不会使原任务等待自身。
- 每次实际模型调用检查完整输入、工具定义、输出预留与安全余量。工具增长可在闭合轮次后生成执行私有摘要；原消息所有者先记录工具终态及已确认效果，摘要再读取事实。原工具不重放，私有正文不发布为群聊摘要或 Memory。
- 工作流并行审查与两轮返工中，长上游正文可私有压缩，迭代、attempt、结构化结果和中断事实保持准确。嵌套维护的框架事件不串入父模型调用或 usage；采用凭据按实际调用序号对应。
- 根任务停止、单独停止维护、禁用策略、成员撤权、原来源/模型变化及重启均有明确终态。私有摘要生成与真正送入原任务模型的采用记录分别表达。

## 覆盖边界

环境为 WSL2/Linux、Python 3.12、Node 24、Chromium、隔离 SQLite 和真实进程测试 World。估算沿用保守 UTF-8 口径，fake 通过不代表真实厂商的摘要语义质量或精确 Token 用量；未调用真实 Provider。PostgreSQL 仅离线编译，没有实例验证；没有 Windows 原生、其他浏览器或移动设备实机证据。

单条必需材料连摘要模型也无法容纳、固定规则本身超窗、必要执行事实过大或原链额度不足时安全拒绝或保留原材料，不承诺任何输入都能压缩。目标未达到时显示实际规模，不删除最近消息或未知副作用。Skills/MCP 完整产品模块、能力知识图谱和世界 Orchestrator 仍属于后续范围。

## 当前可观察事实

| 计数 | 定义与边界 |
|---|---|
| 模型决策轮次 | 图进入一次模型决策节点；当前拓扑每次前置 prompt 回调对应一次模型调用。只在受控测试中独立观察，不新增持久化字段。失败后再次决策也消耗一次，不能按成功数计预算。 |
| 模型调用开始/完成 | `ProviderCallStarted/Completed` 与 `provider_call_index/count` 来自框架模型回调。完成只表示本次模型调用成功返回；失败可有开始无完成。当前不得称为精确 HTTP 尝试数。 |
| HTTP 尝试/重试 | SDK 可在一次模型调用内部进行多次传输；现行日志未独立完整观测，应标为未知，不填零，不用模型调用数推算。 |
| 工具提议 | 模型返回的工具调用，包括预算阻止派发者。提议不等于执行。 |
| 实际工具调用 | `ToolCallStarted` 表示进入工具路径；仍可能在权限、准入或预检处拒绝，不等于文件已提交。结束和提交凭据分别核对。 |
| 文件节点 | 一次批量 write/edit 中的 items；不是工具调用数。replacements 是单文件内片段数，不另算文件节点。实际节点状态以工具结果为准。 |
| 图步数 | 防腐层内的 super-step，取决于拓扑和锁定版本；并行工具不按工具个数逐个累加为图步。不能作为产品的“工具余额”。 |
| Token 与时间 | Token 仅使用厂商报告，缺失保持未知；现有各调用耗时不等于已实现统一任务墙钟预算。 |

现有标识、Owner/Guest、私有详情、日志白名单不变；不新增预算配置、数据库字段或 API，不记录 prompt/参数正文。
同一响应的预算未派发事实、取消与结果收口以[执行事实](execution-facts.md#小阶段-5图预算阻止派发的提议)为准。

## T4.1 历史基线

T4.1 时默认图上限为 15。LangGraph 0.2.74 的当前拓扑中，持续工具调用的模型前置剩余步数为 14、12、10、8、6、4、2、0。
前七轮工具可执行；第八轮模型已被请求，若返回工具提议，框架在响应后阻止派发。调整到 16 时为 15、13、11、9、7、5、3、1，仍是七轮工具执行。
这只描述已测试的持续工具拓扑，不是所有图、return_direct、纯文本结束或未来版本的换算公式。
当时确认一处误判边界：完成七轮工具后，第八次纯文本在 15 步（remaining_steps=0）下仍被标为 graph_budget，尽管模型文本已经到达；相同脚本在 16 步下 completed。原因是锁定框架与当前镜像判断对空工具列表使用 all(...)，剩余零步时空列表也满足条件。T4.2 已修正该误判，15/16 的纯文本回归均要求正常完成；本节仅保留历史取证，不作为现行终态契约。
不为解释停止原因追加模型请求。SDK 重试耗时包含在对应模型调用耗时中，失败尝试的厂商用量若未报告不可补算。

## T4.2 实施契约

内部 decision_limit 取 1..256，默认 8 为本次兼容过渡值（沿用既有约八次模型请求量级），不是 T4.3 的最终产品默认；不新增配置 UI 或环境设置。
每次图模型前置入口先检查并占用一个决策额度，失败不退还；到达额度后禁止下一次模型请求，最后已接纳工具先交接结果。SDK 内部重试不另算决策。
未显式指定图保护值时使用 2×decision_limit+2，余量仅适用于当前无压缩/路由扩展的拓扑并有边界回归；产品决策次数仍直接计数。内部强制图限制保留诊断用途，不把公式作为跨版本承诺。
正常最终响应优先于额度判定；空工具列表不触发派发预算。显式截断/内容过滤/无效工具参数不派发工具，按 PROVIDER_RESPONSE_INCOMPLETE 或 AGENT_PROTOCOL_ERROR 收尾；不以文本内容推断成功。
新增兼容停止原因 decision_budget，消息 status=stopped，表示无下一次决策额度；graph_budget 保留底层保护与旧记录语义。已开始工具仍沿用权限、取消和凭据保护，不新增自动恢复或回合总结。

## 保留的实际依赖

| 要做的能力 | 需要解决的前置问题 | 可以解除的旧绑定 |
|---|---|---|
| 会话导出/导入 | 明确当前支持的数据范围、格式版本、资源重建和敏感数据边界 | 不依赖未实现的编排或长期记忆；未来字段可通过格式兼容演进。 |
| 群聊文件工具（已实现） | 已覆盖资源绑定、触发者/角色授权、串行租用交接、停止与成员撤销；命令/Shell/服务仍限单聊 | 不依赖 Git 仓库；当前契约见工作区协议。 |
| 图管理协调执行 | 本群任命资格、Owner 本次协调请求、目标定义/运行及明确能力范围；新入口可早于 workflow run | 任命或 phase 名称不能直接代表图编辑授权；普通角色执行不继承管理工具。 |
| 图编辑与运行重规划 | 按 ID 的原子操作、独立图版本、授权/引用校验、准确激活关联及安全派发生效点 | 复用 JSON 与 React Flow，不要求图数据库、Git/worktree 或重做并行引擎。 |
| 任务工具分配 | 群协调者提出需求，后台验证工具集合/资源范围；schema、上下文和执行检查一致 | 不修改角色全局配置，不通过模型自述授予权限，不等待世界 Orchestrator 或自动生成整张图。 |
| 并行分支与汇合 | 就绪节点集合、多活跃执行、确定性依赖交接、共享读与互斥修改、取消和失败汇总 | 不独占整个角色执行期；普通任务并行不依赖 Git/worktree。 |
| 条件循环与图修订衔接 | 复用已有条件/迭代/尝试及共享预算，新增未来轮次适用的明确图版本 | 不用失败重试代替正常循环，不新增固定轮数或费用门槛，不暗中扩大循环支持范围。 |
| Git/worktree | Owner 授权的 Repository、路径/版本校验、工作区创建/回收与冲突处理 | 不依赖导出、MCP、Memory；原生搜索已经实现，可直接复用。 |
| 独立分支同时修改 | 明确写入隔离、版本冲突、结果交接与合并/取消语义 | 与本阶段共享工作区修改互斥分开；worktree 是可选方案，选用后才形成相应依赖。 |
| Checkpoint/Memory | 上下文边界、来源/版本、失效与权限隔离，失败回退 | 不要求先完成全部代码协作能力；二者也不必绑定交付。 |

具体任务采用其中一项时，再补齐该项设计与验收；无需为调整普通任务顺序重审全部历史计划。现有 Owner/Guest、Shell 审批、凭据和未知副作用处理边界继续适用。

新计划应明确状态、目标、采用范围、待解决取舍与验收方式。已完成内容的当前字段/限制只在领域协议维护，阶段摘要引用协议和验证记录；旧验收和提交方式不自动约束维护任务。具体工作规则见 [AGENTS.md](../../AGENTS.md)。

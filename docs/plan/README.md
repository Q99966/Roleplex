## 后续执行顺序建议

会话概览换绑与群聊文件工具已经落地，可操作工作流首版已实现。其内部实施顺序见专项计划；其他需求仍按实际价值和依赖独立安排，不重新建立必须逐项完成的长链。

| 建议顺序 | 工作 | 相比旧排期的调整 |
|---|---|---|
| 已实现 | 会话内可操作工作流图 | 工作区入口和群聊文件工具已完成，直接承接；画布覆盖主聊天区，交付可运行、可查看、可干预的串行流程。 |
| 后续按目标选择 | 自动分工 Orchestrator，或 Repository/Git 只读能力 | 工作流先支持用户明确编排；自动分工可复用流程运行与节点事实，不要求先有 Git/worktree。仓库能力独立安排。 |
| 写入隔离具备后 | 并行代码协作 | 先解决资源授权、版本冲突和写入隔离；若选择 worktree，则先完成 Repository/Git 与 worktree 生命周期。 |
| 可独立安排 | 会话导出/导入、Guest 邀请、MCP 接入及现有流程维护 | 不等待工作流、编排或 Checkpoint 全部完成，也不把这些能力捆成一个任务。 |
| 按实际瓶颈插入 | Checkpoint、缓存优化、运行中原生编辑、长期记忆与其他能力库 | Checkpoint 可在长会话容量成为问题时提前；Memory 不作为聊天/导出的前置。运行中编辑单独处理并发与服务生命周期，不与搜索/批量修改绑定。 |

## 保留的实际依赖

| 要做的能力 | 需要解决的前置问题 | 可以解除的旧绑定 |
|---|---|---|
| 会话导出/导入 | 明确当前支持的数据范围、格式版本、资源重建和敏感数据边界 | 不依赖未实现的编排或长期记忆；未来字段可通过格式兼容演进。 |
| 群聊文件工具（已实现） | 已覆盖资源绑定、触发者/角色授权、串行租用交接、停止与成员撤销；命令/Shell/服务仍限单聊 | 不依赖 Git 仓库；当前契约见工作区协议。 |
| 可操作工作流图（当前计划） | 运行快照、节点尝试、精确控制目标、依赖结果交接、群聊节点事实核对与恢复；复用既有调度和权限 | 不重做工作区入口/群聊工具，不等待 Git/worktree 或自动分工。 |
| 自动分工 Orchestrator | 授权参与者、任务分派、取消与失败汇总；复用工作流的执行关联，有限并行按需要引入 | 文本编排不依赖 worktree；已有 E0 不必重做。 |
| Git/worktree | Owner 授权的 Repository、路径/版本校验、工作区创建/回收与冲突处理 | 不依赖导出、MCP、Memory；原生搜索已经实现，可直接复用。 |
| 并行文件修改 | 明确写入隔离、版本冲突、结果交接与取消恢复 | 不能仅靠会话队列或多 worker；worktree 是可选设计方案，选用后才形成相应依赖。 |
| Checkpoint/Memory | 上下文边界、来源/版本、失效与权限隔离，失败回退 | 不要求先完成全部代码协作能力；二者也不必绑定交付。 |

具体任务采用其中一项时，再补齐该项设计与验收；无需为调整普通任务顺序重审全部历史计划。现有 Owner/Guest、Shell 审批、凭据和未知副作用处理边界继续适用。

新计划应明确状态、目标、采用范围、待解决取舍与验收方式。已完成内容的当前字段/限制只在领域协议维护，阶段摘要引用协议和验证记录；旧验收和提交方式不自动约束维护任务。具体工作规则见 [AGENTS.md](../../AGENTS.md)。

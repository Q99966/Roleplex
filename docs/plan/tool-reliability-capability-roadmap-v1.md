## 一、目标、范围和优先级

平台应逐步具备完整能力库，但每个角色只获得经过授权、适合任务的子集。普通聊天、编程、角色扮演可以共享
执行基础设施，不共享全部资源可见性或状态修改权限。工具围绕工作流程而非逐个 REST 接口设计；参考
[Anthropic 工具设计经验](https://www.anthropic.com/engineering/writing-tools-for-agents)，不以工具数量衡量完备程度。

近期目标：合理请求尽量一次完成，短时繁忙在工具层有界消化；无论在哪里停止，已确认动作不能被后续回答抹掉。
远期目标：补齐编程与多角色协作流程，同时保持角色扮演、知识、浏览器等领域的独立规则与授权。

方案分两层，批准边界必须分开：

- **近期 T0–T4 修正轨道**：执行事实/收尾、搜索定位与范围读取（含预算/排队）、多片段编辑、可配置执行预算。确认后仍分切片实施、验收和提交。

  的前置、权限及独立批准要求继续有效。动态工具发现、跨群调度、长期记忆、沙箱均不因本方案而自动开放。

现有能力与范围以 README 和领域协议为准，这里只列本方案依赖的关键事实：

| 已有基础 | 当前缺口 |
|---|---|
| 持久 execution、工具调用身份、领域事件、原位工具卡 | 收尾上下文未完整接入本轮执行事实；未配对调用被粗略归因为额度用尽 |

| W1c Shell 逐次审批、W1d runtime_id 与 /ps、S1 发现、S2 诊断 | 停止原因/预算提示和其他工具错误还需统一表达，不需要再造服务查询工具 |
| ContextBuilder、上下文预算、用户停止、异常收尾入口 | 图步数默认 15，不是 15 次工具调用；硬上限和用户可理解预算尚未分层 |

修复前的 `_wrap_up` 使用原始输入与收尾提示，没有本轮完整工具结果；已累积正文只在最终输出拼接，不成为收尾输入。
这会造成“前文已操作，后文又否认”的风险。修复必须基于执行事实，不通过修改提示词要求模型更自信。

身份必须区分：generation/execution 是 Agent 执行身份，call_id 是工具调用身份，runtime_id 是托管进程/服务身份，
未来 task_id 是业务任务身份。保持现有名字，不把它们统一改成含义模糊的 execution_id，也不用 PID 替代任何资源身份。

## 三、统一基础规范：同一边界，不是一个万能入口

### 3.1 权限与能力暴露

- 复用现有工厂、守卫、资源授权和领域事件边界；“统一执行”不表示每个工具共用一把全局锁或同一风险等级。
- 有效能力是产品已实现能力、Owner/角色配置、当前会话/任务授权、资源归属和运行条件的交集，执行前再次复核。
- 身份及当前资源由宿主绑定，模型不得通过 role_id、conversation_id、root、权限级别等参数自授权限。
- 不默认给主 Agent 全部权限。委派不能扩大触发者授权，子角色不能靠转发请求获得他人私聊、凭据或被禁止的执行能力。
- 当前原生文件、Shell、服务工具的 Owner single 边界保持；群聊调用需要原里程碑的资源绑定和权限设计，不能仅加工具按钮。
- 角色工具包先作为配置模板，不重写已有角色授权；工具很多以后才评估动态发现/加载。发现到工具不等于获准执行。

### 3.2 事实、推断与验收分开

| 信息层 | 例子 | 使用规则 |
|---|---|---|
| 执行事实 | 文件已确认提交、命令退出 0、服务在某时刻通过健康检查 | 来自对应执行层/登记/凭据，保留时间、版本、范围及来源引用 |
| 模型推断 | “应该修好了”“我准备运行测试” | 可作为对话内容，不覆盖执行事实，不自动升级为任务完成 |
| 验收结论 | 某版本的指定测试或实际页面验证通过 | 绑定验证范围/版本与证据，不把部分通过扩大为整体完成 |

“目录曾经为空”和“某版本写入成功”都可以是真实历史；后者不是当前目录永久状态，前者也不能覆盖后者。
需要当前状态时重新查询资源，并明确观察时间；不能为了补造历史而读取当前文件或当前进程状态。

### 3.3 反馈与重试

复用现有错误码和 S2 可选诊断，不全盘替换现有结果。各领域兼容补充 reason、phase、执行/提交状态、
实际值/上限/单位、子项位置和 recovery；这些是统一语义，最终字段按领域定稿，不强迫所有工具返回完全相同的 JSON。
请求参数、内容字节、完整结果 JSON、在途内存和模型 token 是不同预算，不能混为一个“太大”。

| 原因 | 恢复行为 |
|---|---|
| 参数或范围非法 | 修改参数；原样重试没有意义 |
| 内容达到预算 | 按版本与续读位置继续，明确未覆盖范围 |
| 排队满/超时且尚未执行 | 有界等待后可重试，不让相同调用无限排队 |
| hash/匹配冲突 | 重新读取后重定修改，不猜 hash 或扩大匹配 |
| 权限/审批拒绝 | 不换工具绕过，不通过委派洗掉拒绝 |
| 可能已有副作用，结果未确认 | 先核查已有事实和资源；禁止盲目重写、重启或再次发送 |

执行状态与副作用分别表达：failed 不自动等于 applied=false，exit_code=0 不等于任务完成，未采集 diff 不等于无修改。
生命周期来源沿用同一 Trace；正式日志仅留白名单摘要。完整诊断、路径、日志/源码按 Owner 私有详情规则处理，
不能因统一反馈而广播给 Guest。外部网页/文件/工具正文作为数据，不可改变系统指令、授权或审批。

### 5.1 调用级证据保留

沿用现有 reducer、原生写入提交凭据、工具结果与服务登记保存具体调用证据，不再另建回合统计视图。
不得仅从 ToolCall 的输出长度、模型正文或机器日志推断成功，也不每轮追加总结。

至少保留：原 execution/call/item/runtime 关联、目标引用、发生顺序、观察时间、执行状态、提交/副作用状态、
版本证据、结果记录是否完整、diff/日志覆盖情况，以及停止原因。状态可映射未派发、执行中、成功、失败、拒绝、
取消、未确认，但不为统一命名破坏现有业务终态。

原生文件记录回答“本次提交了什么”；Shell/MCP/服务记录回答“什么执行已确认、哪些副作用未采集”。
Shell 退出 0 不能据此列出它修改的所有文件，未知/MCP 工具不自动获得完整原始输出采集权限。
长输出压缩时先保留事实与版本引用，后保留必要有界片段；缺失/超限明确标记，不靠猜测补齐。

### 5.2 停止原因与收尾上下文

明确区分正常完成、用户取消、已证实的执行步数/时间预算触顶、Provider 失败、未配对调用/协议异常和应用中断。
没有充分证据时用“执行异常/结果待确认”，不得仅凭 pending tool calls 推断额度耗尽，更不能推断供应商余额不足。

T1 关闭缺少本轮事实的额外模型收尾请求；正常回答仍走原模型循环。具体执行状态留在工具记录中，
不注入普通历史，不改变原正常回答正文。中断后确需恢复或收尾时，再由独立恢复阶段按需构造状态交接。
交接必须核对具体操作、版本、权限与未知结果，保持厂商调用/结果配对合法；不直接重放有副作用的操作。

### 5.3 停止时的状态保存

正常和异常回合均不生成统计摘要；聊天保留原工具卡、Owner 详情和简短停止原因。
用户停止、预算停止或 Provider 故障不额外发起收费模型请求，不递归“再次收尾”。
现有消息/事实仍由明确所有者修改；终态前有限等待已启动操作收口，超时标未知，迟到结果按既有身份/revision
由原所有者或合法恢复路径归并，不让后台任务静默覆盖终态。进程重启只恢复有证据的事实，不重放业务工具。
服务已移交后的保留策略遵守 W1d：结束回答或用户停止生成不自动停止已托管服务，移交前取消仍需正常回收。

T1 退出条件：已写文件后触顶仍保留已提交证据；结果丢失不报告未执行；缺失工具配对不假冒触顶；不再调用不完整收尾；
用户停止不新增模型请求；新回复无统计摘要，旧摘要不注入历史；刷新/重连、权限撤销和日志脱敏均通过。
T1 不增加运行预算，也不实现恢复任务、长期记忆产品。

### 6.1 范围、顺序与完成标准

本节是 T2 范围和验收的权威位置，取代原 W2b 中“首次新增原生文件搜索”的安排。首版在当前 Owner single、
已绑定 managed_directory 上实现，不依赖 Repository Binding 或 MCP；不提前开放群聊工具、Git、写协作或长期索引。

T2 按两个依赖步骤实施，仍以搜索/读取完整流程作为本阶段验收：

1. **预算与准入基础**：修正申请额度相加拒绝，统一读取准入、取消与版本/输出预算原语。
2. **搜索定位＋范围读取**：新增 workspace_search，给 workspace_read 配套按行模式；从未知位置的目标代码
   搜索到行号，再有界读取上下文。只有两个能力配套通过后，才能宣称本阶段交付，不能只发布一组行号参数。

默认工作流程为：搜索文件名/文本 → 取得路径、匹配行号及少量上下文 → 读取所需行范围 → 必要时扩展范围 →
修改前校验文件版本。已知路径/行号时允许直接读取，不强迫每次 read 前执行一次 search。

### 6.2 workspace_search：定位能力与安全边界

- 首版支持工作区相对路径/文件名匹配和 UTF-8 文本字面搜索。范围由当前 binding 绑定，模型不能指定宿主绝对根。
  文件模式的通配语法、大小写行为和 Unicode 规则须在领域协议定稿；首版不支持用户正则、任意 Shell 或动态命令参数。
- 文本结果返回相对路径、从 1 开始的匹配行号及有界上下文；文件名结果只证明找到候选路径，不伪造文本匹配行号。
  输出按确定的路径/行号顺序组织。空结果必须区分“已检查范围内无匹配”和“扫描因预算/权限/错误未完成”。
- 独立限制遍历条目数、实际扫描文件数/字节、单文件可扫描量、耗时、匹配数、上下文行数、在途内存及最终 JSON。
  不能用返回匹配数上限代替扫描上限；达到预算要报告未覆盖范围和下一步缩小路径/查询的建议。
- 系统敏感路径、凭据文件和链接边界沿用原生文件规则，遍历目录、打开文件前均检查；不跟随 symlink/junction/reparse。
  默认排除 .git、依赖缓存、构建产物等高噪声目录，具体集合在协议中统一维护；普通性能排除与不可放宽的安全拒绝集分开。
  Owner 是否可扩展普通扫描范围在编码前定稿，模型不能通过 include 参数解除安全限制。
- 首版每次按需扫描，无后台全盘索引、数据库专属全文检索、向量库或语义搜索。优先复用有界文件遍历/读取原语；
  实现选型不改变输入是数据的边界，不将查询交给 Shell 解释，也不启动一个需要额外安装的隐式搜索服务。
- 工作区沿用原生文件能力开关，角色单独显式启用 workspace_search；旧角色不自动获得该工具。
  文件内容可能发送给厂商，仍按当前 dangerous/Owner single 边界处理，不能因为只读就自动标 safe。

### 6.3 workspace_read：按行模式与大文件小范围读取

保留原 workspace_read 名称和开关；旧 path/items 字节模式继续兼容。行模式首版同时支持单文件和 items 节点，
每个文件节点只能选择一种模式，不能混用行号与 offset_bytes/max_bytes 来规避预算；字段名称与校验在领域协议定稿。

- 行号从 1 开始，指定起止行，区间两端包含；省略结束行时使用有限默认行数，不表示读到文件末尾。
  固定 LF、CRLF、末行无换行、空文件、超出 EOF、无效/反向区间的语义，返回实际行范围与明确的 EOF/截断状态。
- 逐步返回完整行，受行数和内容字节预算双重约束。单行本身超预算时明确报告不能完整返回，并给出字节模式分段建议；
  不把截断片段冒充完整行，不静默越过该行或扩大预算。UTF-8 字节模式也不截坏字符。
- 区分“允许扫描多大的文件”和“允许返回多少内容”。首版必须验证超过现有 1 MiB 文件上限的受控文本文件可以
  读取一个小行范围；读取扫描上限通过基准定稿，不沿用写入大小检查把合理的范围请求一律拒绝。
  write/edit 的现有文件大小、版本冲突与停服规则保持独立，本切片不据此开放大文件写入。
- 按流式扫描定位行号、校验 UTF-8、保留目标片段；不先把整份大文件或整批文件装进内存。
  深行号定位和全文件 hash 仍可能需要扫描大量字节，计量必须如实区分扫描量与返回量。

### 6.4 搜索 → 读取 → 编辑的版本一致性

搜索是一次观察，路径和行号不是未来不变的定位结果。搜索完成后文件可能被外部编辑器、Shell 或服务改变。
完整扫描且能核验稳定版本时可以返回全文件 SHA-256；仅扫描前缀、预算耗尽或不能确认完整版本时必须明确版本未确认，
不能把 mtime、size、片段 hash 当成可传给 expected_sha256 的全文件凭据。

范围读取接受已知的版本约束，发现不匹配时拒绝拼接或提示重新定位；没有可信版本时进行新的读取观察，
不能声称拿到的是搜索时的同一快照。成功读取应在独立扫描预算内取得全文件 hash；无法完成时不能返回假 hash 或
可编辑凭据。只给版本元数据也不能假称已完成全文件内容验证。

hash 计算和定位尽量复用同一次有界扫描，检测扫描前后可观察到的文件变化并明确拒绝/降级；不承诺已隔离外部写入。
续读基于读取实际返回的位置和版本，不自动续读到无穷；跨版本变化重新定位。不得为补齐 hash 无视扫描/时间预算。

### 6.5 实际内容预算与数值定稿

items 的“申请额度相加即拒绝”改为按实际返回内容分配预算。这是语义变更，须同步说明、schema、客户端与测试：

- 参数 JSON、扫描量、返回内容、完整 JSON、模型 token 分开计量。参数预检拒绝说明尚未开始读取及对应限制。
- 每项上限表示期望返回量，按请求顺序使用剩余整批内容额度，只扣实际返回的 UTF-8 字节；失败项不消耗正文额度。
- 完整读取、部分读取、因整批预算未读取、实际读取失败各自有状态；保留所有节点身份，不只返回成功前缀。
- 完整 JSON 为全部状态、版本与游标预留空间，必要时进一步缩短正文；不能截断结构化输出或丢失字段。
- 读取内容先由主机配置控制，模型不能自己提高整批上限；普通单文件与 items 默认值要有一致、可解释的依据。

当前 16 KiB 参数、1 MiB 文件、32 KiB 批次内容、64 KiB JSON 只作为对比基线；搜索 200 个匹配是原 W2b 的候选值，
均不直接升级为 T2 的最终默认承诺。通过常见源码、多文件组合、超长行和大文本的小范围读取测试，分别定稿默认值与硬上限，
同时报告扫描字节/耗时、返回字节、内存峰值、可避免拒绝/续读次数和独立验收结果。不能因为模型通常会选文件就取消兜底，
也不能维持过低额度逼模型反复续读。真实 token/cache usage 只用厂商返回值，不以本地估算冒充实测。

### 6.6 有界准入、取消与计量

read 的旧 path、items、行模式与 search 共享文件扫描准入和资源预算，不能切换工具或参数形式绕过保护。
每进程执行 2、等待 8、最长等待 3 秒仅为原读取候选起点，加入搜索后需重做规模、公平性与取消测试；不是产品默认承诺。

队列、排队请求字节和外围等待者同时有界，满时立即拒绝。每次调用在内部完成排队 → 授权复核 → 扫描 → 返回，
不要求模型查询排队状态。扫描子任务也必须受限，不能在持有共享槽位时再次无界排队申请同一槽位造成死锁。
搜索不能饿死小范围读取；等待截止受调用剩余预算约束，排队/扫描耗时分开，不靠无限重试消化拥塞。
未执行的取消项必须移出准入，超时、撤权和关闭不泄漏槽位或留下迟到扫描任务；队列位置不是执行授权。

其他命令或 Shell 的读取仍遵守原策略，不宣称全机 I/O 限流，不引入外部队列，也不把自动等待扩展为写入/服务启动重试。
沿用既有 Trace；新增安全扫描/返回计量先更新日志权威设计。日志只保留批准的模式、计数、预算与耗时，
查询原文、私有路径和匹配正文只进入模型结果及 Owner 有界加密详情。

### 6.7 前端与分层验收

角色工具设置将搜索列入文件操作分类，显示中文用途和独立开关；read 的行模式不增加独立工具开关。
聊天沿用实际调用顺序和探索归组，可显示搜索/读取的安全状态；Owner 展开查看匹配路径/行号、实际范围、版本和续读信息，
Guest 不获得查询/匹配正文。预检拒绝显示“未开始读取/搜索”，无匹配、结果截断与失败不能混同。不增加每轮系统总结。

T2 退出条件：

1. 确定性测试从未知位置搜索函数/文本，再按返回行号读取并核对实际内容；已知行号可直接读。
2. 两个小文件各申请较大额度仍成功；大批次输出有完整子项状态；旧字节形式兼容且混合参数不能绕过预算。
3. 超过 1 MiB 的文本可读取小范围，扫描/内存/返回量分别受限；UTF-8、CRLF、超长行、EOF、续读与全文件 hash 语义明确。
4. 搜索后改文件、读取中改文件及跨版本续读有确定性验证；不把过期行号/弱版本当成编辑授权，write/edit 超限规则不变。
5. 多文件/大目录的扫描预算、排除目录、二进制、敏感路径与链接逃逸，以及队列满、超时、取消、撤权、关闭和公平性均有证据。
6. Playwright 真前后端完成 search → 行范围 read 的 happy path 和关键失败/权限路径，验证 Owner 详情、Guest 隔离、刷新与窄屏；
   普通测试使用 fake Provider、逐轮独立数据库/工作区，结束清理资源。
7. 独立真实 Provider 场景让模型定位未告知行号的内容再读取验证，另保留完整两轮开发场景；运行前告知联网费用。
   按实际调用路径报告是否触发 search/行模式，未触发由确定性测试覆盖，不反复计费追求预期工具选择。

每个实施步骤编码前先定稿对应领域协议、错误码、旧客户端降级及数值；实现后才更新 README 可用事实。
单步通过不冒充完整 T2，阶段完成后人工验收、独立提交，再进入 T3。

## 七、T3：一个文件节点支持多个精确替换

在 workspace_edit 的一个文件节点内增加 replacements（候选名），与旧 old_text/new_text 互斥。
旧字段继续兼容；path 与 items 形式保持既定互斥，一个文件仍只有一个基准 expected_sha256。
不通过同一批次重复目标来表达多处修改，不新增独立编辑工具。

2026-09-14 依据评审修订的首版语义：校验原文件/hash → 全部旧片段针对同一原始版本唯一匹配 → 检查区域不重叠 → 构造最终内容 → 一次提交。
不允许后一替换依赖前一替换新生成的文本；需要这种依赖时使用下一次调用。重复片段、重叠区域、空旧片段和非唯一匹配明确拒绝，
不提供顺序/原始版本双模式，不隐式转为模糊定位或正则。本设计替代原未实施的顺序替换方案，实施前同步 schema、领域协议与测试。
任一替换失败丢弃该文件副本，返回替换序号、固定原因及恢复建议，不回显敏感原文。
校验替换数量、整个文件节点和整个批次的输入/内存/计算/输出预算；数量与具体字节限额在实现前基准定稿。

沿用路径/敏感文件、共同原生写锁、最终 hash 复核及现有提交实现；同批规范路径/硬链接别名冲突仍拒绝。
全部替换后内容相同，明确 no-change 语义并复用已有 unchanged diff 状态，不制造虚假的新增修改。
一份原始→最终 diff，而不是把内存中间替换当成多次磁盘提交。diff 失败不改变文件提交事实。
已核对现有文件层：更新先写同目录临时文件、flush/fsync，再最终核对 hash 并 os.replace；新建使用独占打开后写入。
替换校验的全有或全无、替换成功的原子可见性与崩溃持久性分别验收；未提供目录 fsync/恢复验证时，不承诺断电后文件与记录一致，也不声称新建写入中失败必然无残留。

跨文件仍先整批预检、顺序提交；执行时后文件失败不回滚已成功前文件。不会把单文件替换的原子性扩大为跨文件事务，
也不宣称 hash 检查与 replace 已隔离外部编辑器、服务或 Shell 的写入。
服务存续期间的写入策略继续按 S2/S3 权威计划，不因增加 replacements 放开权限。

T3 退出条件：三处替换成功一次提交且调整数组顺序不改变结果；第二/第三处校验失败磁盘不变；依赖新文本的请求拒绝、歧义、重叠、Unicode、换行、no-op、
版本竞争、别名、批次部分成功、取消和 diff 降级明确且有覆盖，旧单项/批次编辑回归通过。

## 八、T4：授权资源内持续执行、准确暂停与继续

### 8.1 目标与分层

正常开发任务应有足够空间自行完成；在用户授权的资源范围内持续工作，必要时准确暂停，并保存后续继续所需事实。
决策轮数作为可配置兜底，不以每个任务固定少量轮数组织执行，也不把提高一个数字当作长任务可靠性已经完成。
上下文压缩解决上下文容量，Provider 重试解决通信故障，执行预算限制授权消耗；三者各自计量，不能互相冒充或隐式续额。
当前实现与测量口径以[执行预算与计数](../protocol/internal/agent-budget.md)为准；以下均为设计，未通过对应阶段验收前不得描述为现有功能。

| 层次 | 职责与边界 |
|---|---|
| 权限与用户控制 | Owner/Guest、资源归属、工具授权、取消和撤权由服务端强制执行，不因任务接近完成而放宽。 |
| 资源预算 | 由 Owner 或部署策略授权，覆盖同一次工作流的资源消耗；不由模型决定是否加额度。 |
| 决策上限 | 对实际进入模型决策的行为直接计数，作为防止长期循环的兜底；失败后重新决策也计入，不按成功次数计算。 |
| 底层图保护 | 仅防腐层使用，防止实现错误导致异常循环；不能成为正常开发任务的常见停止方式，不暴露为工具余额。 |

2026-09-16 用户要求将自定义次数取消 256 硬上限、增加“不限次数”纳入 T4.3c。不限仅关闭决策计数拦截，保留单次请求/工具超时、有限重试、并发控制、权限与用户停止能力；不以前置新增时间、Token 或费用预算作为开放条件。
配置仍由 Owner 管理，沿用当前 World 和工作流作用域，不新增 Guest 配置权、无人值守或子 Agent 能力。首版不引入复杂计费系统或模型进展评分器。

### 8.2 准确停止与结果交接

决策额度在准备发起下一次模型决策之前检查；直接记录决策次数，不通过图步数除以固定系数推算。
最后允许的模型决策若形成有效正常终态，正常结束优先，不能在循环退出后因计数达到上限改标预算耗尽。
正常终态依据响应是否完整、终止元数据、工具提议/结果配对及服务端生命周期判断，不以正文含“完成”判断；截断、协议异常和 Provider 失败不得冒充正常完成。
T4.1 已复现的“七轮工具后第八次纯文本在 15 图步数下误标触顶”必须修复，并覆盖空提议、直接返回工具和最后有效回答。

仅当决策额度耗尽时，最后一次响应中的工具仍可在权限、资源、接纳和时间条件允许下执行，结果保存后不再发起下一次模型请求。
接纳不等于授权永远有效：用户取消、权限撤销或资源软截止到达，均停止尚未开始的动作；已启动操作按既有能力取消和收口，不为“补完整一轮”强行执行剩余工具。
同响应多工具必须明确已接纳、未派发与已开始集合；底层图保护为已接纳操作和结果交接预留空间，不用框架异常随机截断。
文件已提交但取消/响应丢失时保留提交事实，确定未执行与结果未知分开；结果未知先核对，不自动重放。

工具结果已保存不表示模型已经分析过结果。预算终止可以只提供确定性的停止原因、已有工具记录和未完成状态，不强求自然语言总结。
不增加每轮统计摘要，不每轮注入预算提醒，不偷偷请求一次额外模型收尾。未来若引入模型交接请求，必须事前计入总预算且禁止借交接重新进入业务工具循环。

### 8.3 现有预算边界与恢复范围

T4.3a/T4.3c 已完成当前 World 的自定义/不限决策配置。任务开始冻结模式与配置，群聊共享计数，修改默认不改变已接纳任务；固定256及部署ceiling拦截已取消。具体契约仅以[预算协议](../protocol/public/rest/agent-budget.md)为准。
当前具备单次请求/工具超时、模型输出与上下文边界及厂商用量观测；没有整个任务总时间、累计Token或费用封顶。后者不纳入当前 T 剩余工作，也不作为不限模式或事实恢复的前置。
事实交接与执行授权分开：保留用户正常输入消息的现有语义，不通过关键词偷偷重放工具、修改旧快照或启动后台续跑。新消息关联旧执行证据不等于复活旧执行，也不等于追加旧链额度；无需新增额度确认弹窗。
消费计数和调用身份继续沿用已有链路，数据库重试不能重复扣减，缺失快照不冒充不限。未来真正的自动分段或原链自动续跑需要另行设计，不在当前 T 实施。

### 8.4 运行状态与任务结果

分开表达运行结束原因、任务完成判断与验证事实；正常结束只说明本轮生命周期完整，模型报告完成不等于用户验收或实际验证通过。
某个角色结束不等于群聊协作任务完成。字段、状态值和前端展示在对应实施阶段写入权威协议，不在本计划预先承诺尚无服务端支持的接口。
预算停止在具备可靠恢复状态前只表达“已停止/预算耗尽”，不得提前展示“已保存、可继续”。恢复依赖近期执行事实、未派发项、版本和验证记录，不先依赖长期记忆。
继续前重新鉴权并确认工作区绑定与版本；未知结果或失联进程先核对，验证成功仅适用于被验证版本。无法核实时保留未知，不猜测完成状态。

### 8.5 小阶段与退出条件

| 小阶段 | 交付范围 | 验收重点 | 明确不纳入 |
|---|---|---|---|
| T4.1 口径与边界核对 | 已完成离线计数基线、SDK 重试取证与终态误判复现 | 不同图上限、并行工具、逻辑节点、SDK 重试成功/耗尽与最后纯文本 | 修改默认上限、产品配置和恢复 |
| T4.2 准确停止 | 直接决策计数与图保护解耦；修复终态覆盖；最后一轮接纳与结果交接 | 有效最终回答正常结束；额度耗尽不发下一请求；多工具结果完整；取消/撤权优先；异常及截断不误判；无需额外模型总结 | 完整资源预算、配置 UI、跨轮恢复、自动分段 |
| 角色用量观测（已人工验收） | 最近执行与本会话累计、厂商统计持久化、Owner 右栏按需展示 | 缺失不估算、重复不累计、取消/失败记录保留、权限与真实 World 核对 | 新增时间/Token/费用限制、日志回填历史、每轮聊天摘要 |
| T4.3c 自定义与不限决策次数 | 自定义正整数取消固定 256 上限；Owner 可选择不限；冻结模式并保留计数；配套解耦图保护 | 超过 256、模式持久化与旧值兼容、群聊并发、取消/撤权、正常终态及标准真实 World | 新增时间/Token/费用限制、自动恢复、默认改为不限 |
| T4.4 执行链中断事实恢复 | 必要证据保存、结果核对、后续上下文按需交接；沿用自然语言继续习惯 | 主动停止、异常、崩溃和现有群聊的事实关联；未知不重放、权限/版本变化、断线不重复执行 | 新按钮优先、完整Task系统、额度追加流程、自动分段、长期记忆重构 |

T4.2 的内部预算参数、图保护余量及停止事件应先定稿并用确定性测试验证；测试允许覆盖更大预算，不等于选定公开产品默认值。
T4.4 在事实来源、上下文关联与持久化设计定稿后实现，涉及表结构时按工程要求迁移并验证；不再把任务总预算与审批计时列为前置。
每次只推进一个用户授权的小阶段。T4.1 纯排查按既定规则并入下一实施阶段提交，不能因计划补齐自动开始后续编码。

### 8.6 T 收尾验收与后续待办

当前两项剩余工作各自完成确定性、权限、并发及取消测试；用户可见行为通过真实前后端浏览器测试。真实 Provider 使用标准独立 World，说明联网计费，保留角色、会话和结果供人工查看，不能用临时探针替代。
恢复的真实任务覆盖创建→验证→修改→受控中断→继续→再次验证，观察已提交事实是否正确交接、是否无故重传正文、任务是否真实完成；不要求零重复读取，不根据单次Token下降声称普遍收益。
主动停止、Provider异常、后端崩溃和群聊只是不同执行与证据状态，需要共享同一恢复机制的场景测试，不拆成四个新的产品阶段。对未知外部副作用可诚实报告需核对，不承诺任意崩溃恰好一次。

全面完成率/消耗基准、其他大小限制、同文件多范围重复扫描、一次性预算提醒、自动检查点分段和重复失败评分移入后续待办，非当前 T 验收阻塞项。没有新的实际问题证据，不为了这些候选项继续增加读写门槛。

## 九、十二类工具能力库与原里程碑映射

以下名字除明确列为现有者外都是候选概念，不直接承诺工具名、API 或当前可用性。不把后端所有接口逐一包装为工具。

| 能力领域 | 当前可复用基础与建议 | 实施归属/前置 |
|---|---|---|
| 环境、身份、能力 | ContextBuilder/实际工具 schema 注入基础身份和允许能力；即时状态由资源工具查询。按需评审 runtime_context/capabilities_read，不重复静态信息 | T0/T1 先校正上下文新鲜度；查询工具确有需求再小切片；动态 tools_search 后置 |
| 消息、群聊 | 当前会话普通回复由原 reducer 写入；跨会话读取/检索/发送、临时建群和成员操作需新的可见性与授权契约 | 对齐 M4a 后续/M4b 协作设计，不能因已有 REST 即开放 Agent 跨群发送 |
| 任务、编排 | E0 execution 与队列不是业务 task。后续任务定义目标、负责人、依赖、状态、证据和交接，消息通知不代替委派 | M4b 及独立任务持久化评审；依赖 W2/W3 资源隔离，重试/父子权限/取消由运行时负责 |
| 记忆、知识 | 当前历史和项目文档不冒充长期记忆。任务笔记、角色长期记忆、项目决策、即时观察分开；检索结果带来源、版本、范围和失效信息 | 沿用 Memory v0 独立评审及先 role scope、Owner 确认规则；不提前引入项目共享记忆/向量数据库 |
| 工作区文件 | T2 配套交付 search 定位与 read 行范围，含实际预算/准入；T3 提供多片段编辑 | T2 先支持 managed_directory；W2b 复用并适配 Repository，新增 Git 只读查询；patch/worktree 在 W3，move/remove 独立评审 |
| 命令、交互进程 | 复用 workspace_run_command、workspace_run_shell 与现有 runtime_id。不要另造 workspace_exec/命令 execution_id 名字替换现有含义 | 保持 W1b/W1c 边界；命令 profile 扩展按 W3；交互 stdin、持久命令查询另行评审 |
| 服务、预览 | 已有 start/status 列表与单项/logs/stop、/ps、就绪与回收证明、S2 诊断；优先复用，不另造一套 service_* 别名 | S3 单独评审运行中编辑；不自动重启、接管 Docker 或把常驻服务绑回回复组件 |
| 测试、调试 | 当前命令可执行检查，但代码修改、退出 0、测试通过和功能验收分别记录。初期用事实引用关联工具与验证范围 | T1 先可信报告；标准 test_run/result 和 logs_search 视需求封装，复用执行器/结构化日志而非解析整机日志 |
| 联网、浏览器 | 原占位联网按钮已移除，不能视为功能。文档检索、匿名抓取、本地预览、已登录网站操作分权 | 可评审受控只读检索/本地预览切片；M5/MCP 接入路线可复用。外部提交/购买/发消息需独立授权，防 SSRF/凭据泄漏/提示注入 |
| Git、工作树 | 目前原生编辑 diff 不等于 Git diff。明确基线的 status/diff/log/show 与任务 worktree 隔离应分层 | W2a 绑定、W2b 查询、W3 worktree；Git 提交/合并/重置/清理/推送仍需 Owner 明确授权，不能由查询能力隐含授予 |
| 人工交互、申请 | 已有 Shell/服务具体审批；澄清问题、请求协作与权限申请需区分。普通回复不必都变成人工询问工具 | 后续 human_ask/action_request 按真实流程设计；事件通知/自动唤醒由运行时处理，不能让模型 sleep 或轮询保活 |
| 成果登记、交付 | 已有产物相关风险原型不等于完整交付产品。优先登记真实存在、版本明确、接收方可访问的文件/报告/截图引用 | M3 产物主线与后续任务交接评审；不绑定完整会话导入导出，不将注册成功等同产物已验证 |

文件 search 的权限、排除目录、扫描量、正则工作量与匹配结果预算必须服务端控制；不依赖模型自觉避开敏感文件。
workspace_diff 如有必要新增，只查本次采集记录及范围；工作区观察净变化/检查点是另一层，不能冒充具体调用审计。
规则游戏由规则引擎裁决行动，角色仅能读取其可见状态；角色扮演不等于可写工作区或修改隐藏胜负状态。
图片/语音/文档、数据分析、邮件/日历和定时任务均为后续场景能力，明确成本、外部副作用、数据权限与独立批准后再排期。

## 十、角色工具包与两条交付流程

工具包是未来配置模板，不是当前默认授权变更；只装载已实现且通过授权的能力。现有角色不自动追加权限。

| 模板 | 倾向提供 | 不默认提供 |
|---|---|---|
| 普通聊天 | 当前会话、获准资料/记忆读取、必要澄清 | 文件修改、Shell、服务、跨群发送 |
| 角色扮演 | 可见剧情、角色状态、规则允许的行动 | 修改规则结果、读取他人隐藏信息、开发工具 |
| 协调者 | 有权协作的角色、任务/交接、获准通知 | 所有私聊、全库记忆、任意文件和执行权限 |
| 开发者 | 授权工作区文件、按需命令/服务、测试、后续 Git/浏览器 | 任意宿主目录、跨会话停服、自动推送/部署 |
| 测试/评审 | 指定版本只读、受批准的测试执行、结果/浏览器 | 源码修改；测试脚本仍有副作用，不能只因角色叫“评审”而标 safe |

编程交付流程：确认绑定与当前能力 → 有界搜索/读取 → 修改 → 执行/预览 → 独立核验 → 交付产物及证据。
T2 先补齐搜索定位与范围读取；W2b 负责仓库/Git，浏览器能力仍另行规划，不以某个工具切片冒充完整开发流程。

协作交付流程：查询可协作角色 → 明确任务与验收 → 运行时委派 → 获准沟通 → 更新阻塞/进度 → 交接 → 定向通知与唤醒。
参考[多 Agent 委派经验](https://www.anthropic.com/engineering/multi-agent-research-system)，交接至少说明已完成内容、
产物位置、验证证据、未完成事项和接收者；模型描述不代替运行时任务状态或验收方确认。
不得让模型直接消费消息队列，或把再次发消息当成自动重跑有副作用任务。

消息、摘要、记忆、知识、搜索和产物权限必须随来源传播；删掉来源链接不能洗掉不可见性。
权限被撤销/来源失效后，派生内容如何失效和缓存如何清除需在对应协作/记忆协议定稿。
记忆首版优先数据库无关关键词方案，遵守既有 Memory v0 约束；参考
[上下文工程经验](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)，但不照搬其存储栈或全量记忆能力。

## 十一、分层验收与度量

| 场景 | 必须证明 |
|---|---|
| 成功写入后图触顶 | 原工具记录保留已提交事实，不追加缺少执行状态的模型收尾 |
| 未配对调用不一定触顶 | 分清未派发/已派发/未知，历史消息合法，不误报余额或次数用尽 |
| 部分副作用后失去结果 | 保留已确认部分，未知不伪造成未执行，不自动重放 |
| 用户取消或模型失败 | 无隐式新模型请求或递归收尾，已有工具证据与停止原因不丢失 |
| 两个小文件各申请 32 KiB | 不因申请值相加拒绝；实际内容/JSON/内存均受控 |
| 搜索定位后按行读取 | 有真实行号/片段，超 1 MiB 文件的小范围读取可用，版本变化不静默拼接 |
| 内容或参数超预算 | 明确区分预检拒绝、部分读取、预算未覆盖项、续读版本，字段不丢失 |
| 第三个短时并发读取 | 同次调用排队成功；队列满/超时/撤权/取消/关闭不泄漏槽位或迟到执行 |
| 单文件三处替换 | 一次提交/一份 diff；中途不匹配文件不变，同一原始版本匹配、重叠拒绝与 no-op 有明确语义 |
| 批次第二文件提交失败 | 第一文件成功保留，报告部分完成，不宣称整批未修改 |
| 完整工具集两轮页面任务 | 文件/实际页面独立验证，服务按规则跨轮保留和最终回收；不强制某工具路径 |
| 权限/摘要/历史恢复 | Guest/外会话不能从摘要、检索或错误获取不可见原文，刷新/重连保持顺序与身份 |

pytest 使用确定性 Provider，逐轮/逐并发用例隔离数据库；对状态机、取消、副作用与未知结果做故障注入。
每个可见切片有 Playwright 真前后端 happy path 与失败/权限路径，使用受控截图检查桌面/窄屏，真实场景禁用敏感截图/trace/video。
真实 Provider 用独立命令/库/工作区，运行前告知联网费用；普通 CI 不联网计费。复用既有完整两轮场景，
按实际路径分别报告功能通过和工具观察，未触发能力由确定性测试覆盖，不无限重跑来获得想要的路径。
成功、失败、取消均清理本轮资源；过程中的服务存续和最终清理分开，紧急兜底不能掩盖正常回收失败。

度量：停止原因分类准确性、事实矛盾复现是否消除、任务独立验收结果、有效读取/返回字节、排队/授权/读取耗时、
可避免拒绝/模型重试次数、Provider 实际 usage 与成本信息。不得估算厂商 usage 或把模型自称完成当评价标签。
日志只存有界脱敏摘要，原始 Prompt/输出/源码/凭据不进正式日志或失败产物；度量定义与新增事件先更新日志权威文档。

本文件负责跨切片范围和优先级，不替代各领域 wire contract。每切片编码前同步相应服务端 schema、客户端类型、错误码、
兼容/旧记录降级、测试契约和索引；实现后 README 只更新可用事实与入口，不复制字段细节。

T0 已取证，T1 已获授权并实施；T1 人工验收与后续切片关口如下：

4. T3 采用单文件同一原始版本匹配、非重叠替换、全部通过后一次提交，继续保留跨文件非事务与重复目标检查。
5. T4 的配置层级、最终默认值、时间/审批计量和软停止实现需专门定稿，暂不把 64 等候选值当产品承诺。
6. 十二类能力仅确认方向与里程碑映射；跨群通信/任务、长期记忆、浏览器外部操作、Git 写操作和角色扮演规则引擎仍须分别授权。

方案草拟与 T0 阶段不改变业务行为；T1 已在用户明确授权后实施可信收尾修复。
不提高预算、不开放额外工具、不移除停服限制，也不自动提交或推送。

### 11.2 父目录自动创建（小阶段 1，已通过人工验收）

workspace_write 单项与批量均在授权工作区内自动创建缺失父目录，不要求模型先调用 Shell。

核心行为与补充凭据均已实现；测试与覆盖边界见[父目录自动创建测试记录](../testing/workspace-write-parents.md)。

### 11.3 第二阶段：写入准入、提交状态与最小预算收口

先查清锁占用者、等待位置与持有时间，沿用原 Trace 与调用身份；新增诊断字段/错误语义先修改对应权威文档。
观测分为准入等待→工作区锁等待→最终复检→文件操作→结果记录/详情生成。安全关联包含操作/调用/锁身份、获得时间、等待和持有耗时；不记录命令或正文。
锁持有者、Shell/命令、diff 或重入仅是排查候选；先证据后改锁范围。可沿用既有主错误码加结构化阶段/原因，不先铺开新错误码。
区分“执行名额满”“等待队列满”“锁等待超时”和“实际写入失败”，不得继续用单个繁忙标签掩盖原因。

单项与批量 write/edit 统一走有界写入准入，设置活跃数、等待数、排队输入字节及截止；具体值通过并发基准定稿。
不照搬 T2 的 2/8/3 数值。准入与锁等待共用协调截止，阶段切换不能重置完整等待时长；不得先占执行槽再无限等锁。
单工作区串行能力与全局容量分别测量；进程内锁不提供跨进程互斥，当前支持拓扑与其他进程边界必须明确。
读取/搜索队列和写入队列的关系单独说明，不让长写入无界占用只读容量，也不无条件把全部工具串行化。
梳理与 Shell/结构化命令共享锁的持有范围；只缩短不必要的临界区，保留既有停服与写入互斥规则。

已生成的参数留在当前工具调用内有界等待，无需模型查询排队状态或重新输出代码。
这是执行前准入，不是自动重放：等待结束重新检查权限、资源状态和文件版本；已经提交不重复执行，结果未知不盲重试。
最终复检与提交在当前平台管理的有效互斥保护内，不能复检后退出锁再提交。批量执行阶段遇失败停止后续项，保留此前已提交项，避免异常类型偶然决定是否继续。
取消、超时、撤权、关闭后不能迟到写入；不引入跨进程参数持久化、收费请求自动重试或崩溃自动恢复。

调用结果契约必须区分：未获准入/锁且无文件提交、全批预检拒绝、仅目录副作用、部分文件提交、提交后取消/响应丢失、结果未知。
最小提交证据与可降级 diff/展示详情分开；文件提交与数据库事实记录间的崩溃窗口明确可核对或未知，不承诺 exactly-once。

最小预算可靠性与本阶段一起前移：模型决策、Provider 实际请求/尝试、工具调用、文件节点、图步数及耗时各自计数，不全变成硬限制。
发起模型决策前评估预算，为响应中已接纳工具的结果与终态记录预留空间；同响应多工具的接纳/未派发语义必须确定，不靠图异常偶然截断。
触顶后由 reducer 确定性保留已提交、未执行、未知和停止原因，不额外请求模型总结。检查工具结果配对、历史裁剪及工作区绑定是否保留必要事实。
用户明确继续时的按需事实交接另以小切片定稿，先核对权限、来源、当前版本和未知项；不在所有普通回合注入摘要，不自动恢复或重放。

验收：受控锁占用后释放，原调用只写一次且无额外模型请求；名额/队列/字节满、截止、取消、撤权、关闭均有确定结果；
单项/批量共用额度，跨会话并发和写锁/命令锁竞争可追查，既有服务保护回归不变。
用同步屏障覆盖提交后取消/响应中断、目录副作用、前项成功后项失败、模型请求前和工具接纳边界触顶；确保工具结果记录完整，继续时不会把已提交当未执行。

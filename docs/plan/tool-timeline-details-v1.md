## 问题与目标

用户要求工具出现在回答中的实际执行位置，并可以展开查看执行过程。优化前服务端 `_with_text_part`
把完整文本放到首位；客户端增量与 part 更新重新合并文本；ActiveWorkspace 分别渲染完整回答与工具数组。
这三处共同丢失了“文字 → 工具 → 后续文字”的展示边界，仅改变页面排列无法恢复真实顺序。

目标是新消息在流式生成、终态、刷新、断线重连和服务重启后，都保留工具调用在回答中的位置。
本任务属于 W1b 后的聊天体验优化，不开放 W1c Shell、Repository、MCP 产品接入或 Orchestrator。

## 已确定的顺序与交互方向

- 一条角色消息保留有序文本段与工具 part。工具开始时固定前一文本段，后续文字进入后续文本段。
  工具完成只更新原位置的 part，不把它移动到消息末尾。
- 由现有消息所有者顺序处理，继续使用 revision、event_seq、delta_seq；不另造日志时间线推断消息顺序。
  文本仍节流落库，工具边界和终态落库，不逐 Token 写数据库。
- 客户端增量只更新目标文本段，不能覆盖已有工具 part；快照和事件回放共享同一种有序表示。
- 默认折叠的工具卡显示工具名、执行状态和耗时；展开后查看执行过程和结果。取消、拒绝、超时、异常中断
  各自明确展示，运行中状态可更新；按钮有可访问名称，键盘可展开，状态不只依赖颜色。
- 旧消息缺少可靠分段信息，不能猜测历史调用位置；保留原数据，以“历史执行记录，位置未记录”降级展示。
  不从机器日志或当前最终文本反推、改写历史。
- ContextBuilder 的历史正文按原序拼接，顺序展示元数据不注入稳定 Prompt；不顺带改变 C1 历史语义。

## 详情内容：已批准的边界

原 W1b [命令协议](../protocol/internal/workspace-commands.md)规定 stdout/stderr、路径和原始参数不进入
共享工具卡；[W1b 计划](agent-repository-workspaces-v1.md)也只承诺摘要。本次用户已批准通过独立 Owner 接口查看详情，
公开工具卡和机器日志仍保持安全摘要边界。

采用 Owner 专属的有界执行详情：

- 当前 World Owner 可主动展开查看已实现工作区工具的输入和结果；Guest 只获取允许公开的摘要。
- 详情作为独立的受保护业务记录，不混入普通消息/WS payload、机器日志、审计摘要或测试报告。
  使用 World 密钥加密持久化，迁移 `0007_tool_execution_details`；输入/输出各限 64 KiB，保留 7 天。
  过期后接口不再返回正文，启动清除过期密文；记录随消息物理删除级联删除。具体契约见
  [工具执行详情](../protocol/public/messaging/tool-details.md)。后续预留迁移编号顺延，不提前实施其能力。
- 不新增主机文件读取、日志文件下载或任意命令执行入口；未知工具默认仅提供摘要，不自动采集任意输入输出。
- 原始内容按文本展示，不执行 HTML、脚本或终端控制序列。未采集、被截断、已清理、权限不足与仍在执行
  必须可区分；历史调用不伪造输入输出。

执行中展示已捕获输入、开始时间和等待结果状态；本阶段在工具完成后展示结果，不增加逐输出块的持久化或广播。

## 验收要求

- fake Provider 确定性产出“前置文字 → 工具 A → 中间文字 → 工具 B → 最终回答”，断言流式、终态和刷新
  后的顺序一致，增量不删除工具卡，工具状态更新不移动位置。
- 覆盖 Unicode 文本、相邻工具、无前置文字、取消、失败和启动中断；重复/乱序事件不能回退较新 revision。
- 后端与 WS 测试覆盖断线恢复、重放与快照降级；ContextBuilder 原有历史正文和隔离测试继续通过。
- Playwright 使用真实前后端和 fake Provider 验证有序展示、展开/收起、运行状态、刷新恢复及权限路径，
  在隔离测试工作区中使用无实际价值的内容，并检查截图。
- 若采用 Owner 输入/输出详情，增加 Owner/Guest、资源归属、World 隔离、加密存储、截断及日志不泄漏测试；
  表结构变更必须有 Alembic 迁移、SQLite 重放与 PostgreSQL 离线 SQL 检查。
- 用既有 real-world 入口验证真实工具链的顺序和详情可用性；运行前说明联网计费，关闭 trace/video，并避免
  将原始模型/工具内容保存到浏览器失败产物。

先同步消息、WS、执行详情和必要数据模型协议，再实施；自动验证、人工验收与提交分别记录。

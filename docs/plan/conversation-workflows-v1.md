本文维护下一步工作流模块的范围、交互、执行设计与验收目标。现有功能以领域协议为准；当前 API 与状态以[工作流协议](../protocol/public/rest/workflows.md)为准。实施时在同一变更中补齐对应协议、schema、客户端类型与测试，不从旧里程碑继承额外审批或提交关口。

## 1. 目标与已完成基础

用户在当前会话内安排角色任务、保存流程并启动，能查看每步的实际结果，在失败或停止后核对事实并选择下一次执行。普通聊天和 `@` 串行协作继续可用，使用工作流不成为发送消息的前置条件。

以下两项已经实现，不再列为待开发步骤：

- 会话右侧“概览”显示工作区，Owner 可为已有单聊或群聊绑定、更换、解绑；活动消息链与进程回收继续按现有规则处理。
- Owner 群聊角色按 `@` 顺序串行使用原生 list/read/search/write/edit，各自检查权限并交接工作区租用。群聊命令、Shell 和后台服务仍未开放。

现行契约见[工作区](../protocol/public/rest/workspaces.md)、[会话](../protocol/public/rest/conversations.md)与[Agent 运行时](../protocol/internal/agent-runtime.md)。已有回归入口为 `backend/tests/test_group_workspaces.py` 和 `frontend/tests/commands/group-workspace.spec.ts`；本轮已扩展节点级控制与事实交接验证，入口见末尾。

本轮新增流程定义、一次运行及节点尝试的持久关联、节点级任务交接和可操作画布。现有 `WorkflowBudget` 只是消息链预算；原 `@` 请求一次排入角色序列，本轮另增可编辑流程、人工节点和按节点重试，不改变普通聊天行为。

## 2. 画布覆盖主对话区

- 在现有会话右栏增加“工作流”模块，展示本会话的流程入口、选中运行和进度；点击“展开画布”后，在**主对话窗口原位置覆盖聊天消息区及输入区**。
- 桌面保留应用侧栏与会话导航，画布使用主对话区的可用面积；无需新页面、新标签页或浏览器全屏。节点属性与运行详情在画布内按需展开，右栏继续承担会话模块入口。
- 覆盖期间聊天区不接受点击、输入或键盘焦点；聊天组件状态、未发送草稿、阅读位置和登录会话级 WebSocket 保留。后台流式回复与工作流状态继续接收。
- 画布提供明确的“返回对话”入口；Esc 先关闭节点菜单/弹层，再退出画布。关闭画布恢复原对话位置、草稿与合理焦点，**不表示停止、取消或重新启动流程**。
- 图形编辑草稿按会话保留；保存成功才表示服务端已有对应版本。切换会话或 World 不把旧画布、运行选择或迟到响应带到新上下文，尚未保存的编辑有明确状态及防丢失处理。
- 窄屏同样覆盖主聊天区，节点列表/属性可切换查看，核心编辑与操作不依赖悬停。缩放、平移、适配视图及节点选择提供可访问名称；添加、连接和重排有键盘可用的等价操作。
- 视觉沿用[当前工作台设计](../design/frontend-navigation-theme.md)。这里确定的是覆盖主聊天区的交互；画布库和布局算法在实现时选择，不成为新的前置选型阶段。

## 3. 首个完整版本的操作范围

节点代表一次任务，角色是执行者，同一角色可在多个节点出现。流程归属当前 World 和会话；角色候选来自本会话，单聊与群聊复用同一入口，主要协作验收使用群聊。

| 对象/操作 | 首版行为 |
|---|---|
| 流程定义 | 命名、创建、编辑、保存与复用；保存有版本冲突检查。复用定义创建新运行，不复用旧的执行许可。 |
| 角色任务节点 | 选择角色，填写本步任务、预期产出和需要的上游结果；可以添加、删除、重排及连接依赖，不修改角色的全局系统提示词。 |
| 人工确认节点 | 按需插入业务检查点，可查看结果、确认继续或结束本次流程；未配置时不强制逐步人工验收。工具自身所需审批仍按现有协议执行。 |
| 连线 | 画布可编辑保存分支与环路；首版执行器只接受覆盖全部节点的串行依赖，其他结构在启动前明确拒绝。 |
| 启动 | 根据保存的定义创建运行快照，展示参与角色、任务及工作区；重复点击/网络重发不重复启动。 |
| 查看 | 节点显示真实执行状态；点击查看对应对话、工具调用、文件差异、停止原因和用量，复用现有权限与详情入口。 |
| 停止 | 针对选中的运行停止当前步骤并阻止后续派发，展示实际收口进度；文件已提交的事实保留。 |
| 重试/修订 | 用户选择具体节点，核对上次结果后创建新的尝试，可补充本次要求；保留旧记录，不自动重放整条流程。 |

例如：

```mermaid
flowchart LR
    A[任务目标与工作区] --> B[开发者：创建页面]
    B --> C[审查者：读取、检查与修改]
    C --> D[结果与文件变更]
    D -. 用户选择修订，创建新尝试 .-> B
```

虚线表示用户发起的新尝试，不是首版定义中的自动循环。重做上游后，下游旧结果保留原尝试关联并标明已非本次结果；后续节点明确重新执行或等待用户处理，不能直接沿用旧成功状态。

## 4. 定义、运行与节点尝试

| 概念 | 职责与复用方式 |
|---|---|
| 流程定义与修订 | 保存节点、依赖和编辑布局。保存新版只影响后续启动，不悄悄改变已运行或已结束的实例。 |
| 一次流程运行 | 冻结定义版本、任务输入、参与角色及工作区关联；关联现有会话、触发消息、chain 和预算，负责流程进度及用户控制。 |
| 节点尝试 | 记录节点本次输入、选用的上游尝试和结果引用；角色任务关联已有 generation/execution，重试创建新 execution。人工节点记录决定，不伪造模型执行或 usage。 |
| 工具与副作用事实 | 沿用消息工具 part、私有详情、文件边界证据与运行实例记录；流程只建立必要关联，不复制源码、密文详情或另一套业务 Trace。 |

新增存储仅承载流程定义和控制状态，不替代现有执行事实。表、字段、唯一约束、REST 操作、WS 事件和错误码已按领域定稿并同步迁移；当前 wire schema 由工作流协议维护。

流程与节点的产品状态要区分待执行、执行中、等待人工确认、受阻、停止收口中、已停止、失败/中断和本轮执行结束。旧尝试与当前尝试可辨认；实际工具是否提交、任务是否通过人工检查分别展示，不从模型正文的“完成”推断验收。

节点结果与状态先持久化，再发布事件和派发依赖步骤。重复完成事件、双击确认、确认与停止竞争不能多派发节点；并发编辑采用修订冲突检测。等待人工确认时释放执行 worker、文件 lease 与数据库事务，只保存等待状态。

## 5. 与聊天、调度和上下文衔接

- 在现有会话调度器上增加明确的节点派发/完成衔接，继续由原消息所有者维护流式内容。角色任务沿用 single/group_role 的当前权限判断，不通过新 execution 类型意外丢失安全检查。
- 一个运行内按依赖串行派发，同一角色可被多次选中。现有 `@` 的角色去重/整批排队不能替代节点身份；每步任务使用自身输入和明确关联的上游结果。
- 上下文统一经过 ContextBuilder。首版交接上游角色回复和有权读取的结果引用，文件内容通过接收角色获准的文件工具读取；不能把前一角色的完整私有工具详情直接注入后一角色。
- 普通聊天中断上下文仍按“本角色最近中断回复”选择来源，私有文件核对分支限单聊。本轮工作流另按选中节点/尝试核对原生文件事实，已补齐群聊下的授权与结果交接，不混用最近角色回复。
- 普通聊天继续使用既有入口；图形操作与聊天通过相同执行记录关联，普通消息不会被隐式当作流程节点。聊天补充要求可作为用户明确选择的节点输入，不能偷偷改写运行快照。
- 一次运行沿用现有消息链冻结的共享决策预算，节点切换和人工确认不续额；同一运行内重试继续使用剩余额度。额度不足时用户可以按当前配置显式创建新运行，保留来源关联及旧计数，不增加额外额度审批流程。
- 不因图形化新增总时间、Token、费用限制或固定节点数阈值；现有权限、上下文、单次超时、准入和用户停止继续有效，长流程可按现有 World 配置选择自定义或不限决策次数。

## 6. 停止、重试与资源变化

- 工作流操作精确关联目标运行和节点尝试，不能借用当前“停止会话最新 chain”的接口误停其他任务；运行等待人工确认、没有活跃 generation 时，也能结束流程。
- 停止先封闭后续派发，再取消当前执行并等待已有事实交接。后续节点显示未执行/已取消；已提交、未执行、失败与结果未知分别保留，不将停止理解为回滚。
- 重试前核对该节点可用的提交证据和当前文件版本；过期、缺失、prepared 或保存失败保持未知。新尝试按当前权限执行，不把旧审批当作新授权，不复用中断图状态或重发未知副作用。
- 浏览器断线/刷新从服务端恢复运行快照与事件，不重新启动节点；后端重启按既有中断规则保留已知事实，不自动重放副作用。等待人工确认的记录可恢复展示，继续操作先复核当前权限和资源。
- 启动、派发、继续和实际工具调用都检查 Owner、成员、角色存活、工具开关及工作区归属；流程快照记录输入，不能冻结永不过期的权限。
- 活动运行包含等待人工确认的情况，换绑/解绑不能让前后节点静默使用不同目录。沿用活动任务的处理方式：先停止或完成该运行，再换绑并新建运行；实际等待期间不占用文件锁或 lease。
- 删除会话、切换 World、成员撤销和资源停用与现有收口流程衔接，未执行节点不能继续派发。已登记服务沿用自己的生命周期与回收规则，不从“流程结束”推断全部副作用被撤销。
- Owner 编辑、启动和控制流程；Guest 沿用现有成员可见的聊天/执行摘要，不获得流程管理、目录、模型配置或私有工具详情权限。群聊原生文件能力不自动扩大为 Shell/命令/服务能力。

## 7. 实施顺序

以下是同一个功能的实现顺序，每步解决实际依赖，不另设逐步人工批准或独立提交门槛。

1. **运行模型与契约**：梳理流程/节点/尝试关联，补齐迁移、保存/启动/确认/停止/重试的并发语义以及事件恢复协议；保留现有聊天行为。
2. **串行执行与事实交接**：通过现有调度和 ContextBuilder 完成开发→审查，接入可选人工节点，补齐群聊按节点核对、取消、重试和预算共享。先用确定性用例验证真实文件结果。
3. **右栏入口与覆盖画布**：交付编辑/保存、运行状态、节点详情和控制操作，验证打开/关闭画布时的聊天状态保持。界面开发可与稳定后的服务契约并行。
4. **完整用户流程验收**：真实前后端 + fake Provider 验证编排到运行、异常干预与重连；再执行本计划包含的独立真实 World 协作验证，保留可查看结果。

验收对象是完整可操作模块。Git/worktree、自动分工 Orchestrator、并行写入、自动条件分支/回路和长期记忆不作为本次前置；后续按需求在相同运行事实基础上扩展。

## 8. 验收与文档同步

| 层级 | 必须证明的结果 |
|---|---|
| 定义与持久化 | 保存/刷新一致；冲突可见；缺失角色、无效连线有定位反馈；新定义版本不改变旧运行；同一角色的多个节点不被去重。 |

| 预算与恢复 | 多节点/重试共享额度；不限模式仍可停止；刷新、断线、重复/乱序事件和后端重启恢复真实状态，不重放操作。 |
| 浏览器 | 从右栏打开画布并覆盖主聊天区；编排保存并运行；节点详情定位原消息/diff；返回对话保留草稿、阅读位置且不停止执行；覆盖桌面、窄屏、键盘与焦点。 |
| 关键失败流程 | 在开发节点已提交后停止或撤权，审查节点不继续写；刷新后仍能看到已提交事实；修复条件后，Owner 选择节点重试形成新尝试与明确的后续结果。 |
| 真实 Provider | 通过标准真实 World 专用入口验证开发→审查的实际文件交接和可操作流程，保留 World/角色/会话供查看；精确取消竞争和崩溃窗口由确定性测试证明，不强迫真实模型重复试错。 |

测试沿用[测试指南](../testing/README.md)的命令隔离、目录、清理和结果保留。真实场景已在说明联网计费后按专用入口执行，实际结果及失败重试原因见本轮验证记录。

## 本轮实现记录（2026-09-16）

根据后续用户确认，画布已替换为 React Flow，支持自由布局、保存坐标、连线、分支和环路编辑。拖动仅改布局，当前执行器仍限完整串行路径；分支/循环执行条件和终止语义未开放。
新增三张控制表（迁移0019），角色节点复用原队列、预算和消息 reducer；人工等待释放执行资源，重启不重放。
右栏新增工作流模块，画布在主聊天区覆盖显示；旧聊天继续挂载，inert 隔离交互，返回时保留草稿和阅读位置。
节点尝试精确定位原消息、diff、用量及授权文件事实；重试创建新尝试，可显式选择是否重跑后续步骤。
验证入口与本轮实际结果见[工作流验证记录](../testing/workflows.md)。本计划不作为新增阶段审批或收费测试的重复前置。

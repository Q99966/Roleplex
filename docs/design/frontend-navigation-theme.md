# 工作台侧栏与清爽配色

状态：已实现；原侧栏方案沿用既有验收，工作流第二批验证见[可读性记录](../testing/workflow-readability.md)。复核日期：2026-09-21。维护者：Roleplex。
事实来源：Sidebar.tsx、tailwind.config.js、styles.css、write-diff.css、workflows/ 下的画布与展示模块；验证入口见测试指南。

## 侧栏

会话与角色用顶部标签切换，共用完整列表高度及搜索位置。两类搜索词和滚动位置在本次页面内独立保留，刷新后回到默认会话列表。
切换标签不调用会话导航、不修改 activeConversationId、不清空右侧草稿。角色按名称、标签和描述匹配，列表行显示名称与描述，长名称有完整悬停标题。
右上角新增按钮随标签切换为新建会话或创建角色；回收站、设置与账号入口固定在底部。
角色行支持直接编辑和更多操作入口，复用原角色弹窗，不新增接口或越过 Owner/Guest 权限。
标签支持左右方向键、Home/End 与明确焦点；会话导航和行内控制为独立按钮，避免嵌套交互。

## 配色

采用浅蓝白背景与深蓝灰文字，天空蓝用于主操作/会话选择，薄荷绿用于角色标记；错误仍为红色，警示为金棕色，成功为深绿色。
复用现有 Tailwind 工具类接口，分别定义背景、文字和边框色，不简单反转统一色阶。原 indigo 品牌槽改为天空蓝。
普通 text-white 标题适配深色文字，实色操作按钮保留白字；按用户最新反馈（2026-09-15），代码 diff 与浅色工作台协调：蓝白上下文底色、浅薄荷绿新增、浅玫瑰红删除、深蓝灰代码文字；行号底色略深，保留正负号区分，不只依赖颜色。此前独立深色方案被本次明确取代。
滚动条按用户要求使用暗灰滑块（#52525b），悬停提亮（#71717a），轨道透明，支持 prefers-reduced-motion；不新增主题依赖、字体下载或模型调用。


## 会话工作区入口

右侧“会话概览”模块显示当前工作区；Owner 可展开选择已有目录或“不绑定工作区”，显式保存后完成绑定、更换或解绑。
单聊和群聊共用入口；群聊提示 @ 顺序串行执行和角色独立文件权限。消息链活动时禁用换绑，服务回收沿用会话进程确认。
Guest 仅看到是否绑定，不展示 Owner 目录与修改控件。界面沿用现有颜色、间距及窄屏换行布局。

## 会话右栏

右栏只展示一个当前模块：概览、成员或工作流；当前模块图标作为右上圆形入口，桌面仅绘制四分之一可见窗口，当前分为五个 18° 扇区（概览、成员、工作流、两个不可激活的未开放补位）。选择后顺时针移动，出界项用循环副本从另一侧进入，完成后停到标题位置，文字保持正向；不构造 12 格完整圆盘。圆心 24px、距右上边缘 2px，不保留关闭叉号。窄屏使用紧凑列表，抽屉通过遮罩或 Esc 收起，桌面保留聊天顶部详情开关。透明外角不拦截页面点击。
菜单支持方向键、Home/End、Enter、Esc 和外部点击关闭；选择后返回入口焦点。抽屉约束 Tab 焦点，关闭后返回打开按钮。
面板可收起，模块选择与各模块滚动位置在当前会话页面内保留，切换不清空草稿、不触发新模型请求。
概览复用会话名称/类型/角色数/归档置顶和 Owner 工作区名称；成员使用当前账号已有角色目录；现有 API 未提供 Guest 可见的角色名称时，仅显示会话公开角色编号，不额外读取 Owner 配置。Guest 不显示模型、描述或编辑入口。
群聊成员管理从成员模块进入，进程继续使用原面板和 Owner 权限，工作流从独立模块进入；剩余未开放扇区只作不可点击补位。

“工作流”模块现提供流程定义列表、运行选择与进度；展开画布覆盖主消息和输入区域，保留标题、左侧导航及右栏。
聊天内容仍挂载并接收事件，但覆盖期间设为 inert/aria-hidden，不接受点击和键盘焦点。返回对话不停止运行，恢复原草稿与阅读位置。
节点任务、人工确认、串行路径重排和上游结果选择在画布编辑；运行视图展示对应版本快照，运行图编辑通过独立修订提交。节点详情复用原消息工具卡、diff 与厂商用量。
画布使用按需加载的 React Flow，自定义节点沿用现有摘要卡；拖动只修改位置，坐标保存后刷新恢复。
缩放、平移、适配、缩略图和选择复用 React Flow；分支与环路可编辑保存，v2 执行并行、汇合与显式条件循环，配置不完整在派发前定位拒绝。
连线同时支持连接点拖动和“连线工具”表单；画布选中元素后按 Delete 删除连线或无连接节点，含自环的节点必须先删线。输入框、画布外焦点和运行视图不触发删除；属性面板删除按钮遵守相同约束。
串行重排仍通过属性按钮完成，窄屏属性面板位于画布下方；Esc 先关闭尝试详情，再取消节点选择，最后返回对话。
编辑草稿使用 IndexedDB 保存完整定义、基准版本、运行目标、补充要求和节点选择，连续输入合并写入；页面隐藏、刷新、退出与 HMR 时补写 sessionStorage 恢复日志。恢复前先取得当前 Owner 的服务端分区，按 World、账号及会话创建身份隔离，登录 Token 不进入草稿。认证失效不删除草稿，同一 Owner 再登录可恢复；此存储不提供操作系统级隐私隔离。
刷新优先恢复本标签页的副本，新标签页从最近副本开始独立编辑；恢复不写服务端、不启动运行，脏草稿保留原基准版本并沿用冲突处理。侧栏区分“正在保存”“已保存到此浏览器”和失败，支持恢复其他副本、删除指定副本、失败重试及下载 JSON 备份。手动恢复其他副本前等待当前编辑实际持久化，再切换编辑身份，避免立即刷新覆盖唯一备用日志；失败保留当前编辑并提供备份/重试，不自动淘汰未提交副本。
本地保存不等于“保存流程”：后者才提交服务端版本。清除站点数据会删除本地草稿；浏览器进程在异步写入完成且离开日志写入之前崩溃，末次输入仍有丢失窗口。主存储和离开日志都失败时保留浏览器离开提示。损坏副本跳过但不删除；恢复身份接口不可用时提供重试并暂缓编辑，避免迟到恢复覆盖新输入。
完整状态和控制语义见[工作流协议](../protocol/public/rest/workflows.md)，范围来源见[专项计划](../plan/conversation-workflows-v1.md)。

按用户确认的最终贴边方案，扇形圆心位于右栏右上角，两条直边与栏边对齐；入口圆点独立内收，完整可点击。半径采用右栏可用宽度。盘面、文字和分隔线取自右栏实际配色，选中/悬停仅叠加轻微明暗变化，无独立彩色拼块、亮色外轮廓或厚阴影；菜单采用短名称，完整名称保留在悬停提示和无障碍名称中。

入口按钮使用同背景底色、细灰边框和蓝灰图标。展开后按钮隐藏且禁用焦点/点击，扇区填满圆心，不保留透明开关区域。当前模块可直接收起，其他模块旋转后切换；外部点击或 Esc 关闭。仅在关闭后恢复按钮并返回键盘焦点，未开放扇区不切换也不关闭。

角色卡增加按需展开的“执行用量”，以“最近一次/本会话累计”切换统计范围；沿用浅色卡片和两列指标，不增加顶层模块。只对 Owner 展示，未知/部分记录明确标注；不增加聊天摘要或预算限制。

### 工作流侧栏与节点编辑

流程名称、运行补充要求、添加节点、保存/启动、运行控制与连线表单统一放在右侧“工作流”模块。
画布顶部显示名称、“返回对话”和视图工具栏，保存/启动仍在右栏。运行态在右栏提供“编辑流程定义”，
明确只影响后续新运行。Delete 等说明收进“操作帮助”，不持续占用画布高度。
窄屏通过现有会话详情抽屉操作；添加节点或成功启动后返回画布，失败提示留在抽屉内。

展开为真实节点并查看执行依赖时，编辑态节点被选中且具有焦点后，Tab 在其后插入角色任务，并将焦点移到新节点。原出边由新节点承接，
原后续结果引用保持不变；分支/环结构保留。Shift+Tab、输入控件中的 Tab 和运行视图保持正常焦点导航。
节点属性支持角色任务/人工确认切换，保留任务文字、连线和布局；切为人工确认时移除执行角色，切回角色任务需合法角色与任务。
节点默认按类型配色，允许选择自定义颜色并恢复默认。颜色用于辨识，执行状态仍通过文字表示；运行快照的类型和颜色不随新定义改变。

群协调者在“会话成员”任命，工作流模块提供独立“协调执行”。并发容量、入口和循环声明位于右栏；节点属性配置本任务工具、结构化结果与条件。运行按 activation/iteration 展示，选取精确历史尝试可查看分配、结果、原消息与事实；协调规划/汇总记录也能打开原详情。选择历史运行不重发执行，普通 @ 不变。

### 工作流连线路由

普通边使用圆角折线，通过 `@tisoap/react-flow-smart-edge` 按节点实际尺寸与位置避障，留出节点边缘间距。路由由共享 Provider 在 Worker 中批量计算，拖动时更新；标签、运行状态变化不改变执行依赖。循环回边优先在循环体外侧返回，自环与向左返回的边也走外侧走廊；多条返回边使用不同侧/间距。几何上的返回边不自动变为业务循环。

循环声明的回边显示虚线、箭头和“返回下一轮”；分支优先使用保存的业务文案，缺省为“条件成立/不成立”，悬停和选中可核对实际字段、比较值与来源。自环显示“自环”，普通依赖不重复铺满说明文字。外侧途经点和寻路结果是临时绘图数据，不写入工作流定义；坐标和展示标签按协议保存，刷新重新计算路径。

保留 React Flow 的透明命中区域、键盘选择和 Delete 删除规则。测量/寻路未完成或无法获得路径时保留可选择的虚线回退；节点重叠或通路被封闭时不能保证避障。已有拓扑整理可以改善节点排列，不保证任意图所有边均无交叉。

### 阶段总览与节点细节

复杂图默认展示阶段总览，按自定义展示阶段、显式循环和明确的并行汇合区域收起任务；简单串行图直接显示节点。聚合卡片包含真实节点数、成员摘要和当前运行/等待/失败/反馈计数，循环附轮次、上限及出口。完整相同范围去重，包含关系允许分层展开；交错依赖不强行合并成一个假循环，而是保留展开并说明原因。

“节点细节”显示实际任务、汇合、条件和人工确认；类型用图标/形状区分，角色名、用户颜色和执行状态分别表达。创建编号只作定位。展开循环显示范围、出口和外侧回边；边文案不参与业务判断。

布局按拓扑分层和稳定排序安排主干、并行分支与汇合；合法循环先按区域排布，再展开内部节点，避免夹入无关并行任务。草稿中的未声明环路通过强连通分量降级展示，不补造执行声明。无坐标节点自动布局；增量节点局部安置，已有手动位置保留。“整理布局”只改坐标并可撤销，显式保存后持久化；运行/历史视图的“整理视图”不提交版本。

视图工具栏提供总览/细节、整理/撤销、定位节点、聚焦选中，以及执行依赖/结果交接/反馈处置三个关系图层。反馈卡片可“定位处理路径”；选中节点突出真实上游、下游，其他路径弱化，已有失败/等待/反馈保持可见。默认保持可读缩放，适配全图由用户主动选择；窄屏可通过定位下拉框展开并聚焦某个任务，避免只能看一张缩得很小的图。

展示阶段编辑入口与分支显示名称复用右栏及现有图保存，纯展示修订不重置正在规划/汇总的执行或任务分配。虚拟阶段、关系引用线不能被当成真实任务/控制边删除和连接；所有保存仍基于原节点 ID、业务连线和版本。字段、兼容和历史引用规则见[工作流协议](../protocol/public/rest/workflows.md)。

### 协调规划与图版本

群聊输入 `/plan@协调者 <要求>` 进入仅设计模式，复用 @ 补全，发送前显示新草稿或具体定义。右侧也可“规划 / 调整草稿”；“协调执行”明确授权规划后启动，“让协调者调整运行”限定本次运行，不代签人工确认。

模型提交成功通过版本通知/快照进入同一画布，布局按稳定 ID 保留。已有人工脏草稿遇到新版本显示差异和冲突，提供另存本地草稿或明确采用服务端版本；不静默覆盖。图修改记录区分模型/Owner、定义/运行、已采用/等待边界/未采用；协调记录复用原工具卡。

运行图与模板编辑分开，历史版本只读且按尝试所属图版本展示，旧记录明确标注。未派发部分可编辑，已派发的内容和入边保持冻结；保护节点可由 Owner 在本次协调请求中指定，普通工作角色没有图管理入口。/plan 或画布切换不丢弃聊天草稿与阅读位置。连线仍沿用现有节点避障与外侧回边。

### 节点反馈与局部处置

运行视图集中展示“节点反馈”，默认显示未关闭项，可展开已处置记录。卡片显示分类、来源节点/图版本/轮次/尝试、是否仍为当前来源、处理角色、验证尝试和真实图修改；Owner、工作角色/协调者、系统交接分别标记。正文不自动触发自然语言 @ 派发。

选中尝试的“结果与执行事实”可提交分类反馈；能力缺口额外输入所需工具名，后台核对当时分配与当前授权。卡片内提供处置依据、交给协调者、关联待派发处理节点、等待/复核、核验解决和接受遗留等操作。人工核验必须明确勾选并填写依据，不能只点“完成”抹掉未知结果；冲突保留输入，刷新后核对最新处置。

“协调执行时自动处理节点反馈”由 Owner 在启动前明确勾选，默认关闭；界面说明它允许在本次范围内局部改图并安排验证，沿用原预算。手动流程可逐条委托，完成后的复核属于该条委托。运行和节点分别显示等待反馈，不把它表现成 Provider 异常。

反馈与局部处置、阶段总览与图可读性已接入；全局操作工具栏和唯一上下文面板的收敛仍按[第三批计划](../plan/workflow-feedback-usability-v1.md#4-第三批操作面板整理)推进。

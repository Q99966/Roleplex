## 1. 唯一目标：继续时准确知道之前做到了哪里

用户已经可以直接输入“继续”“下一步”来接着工作。当前不足是下一次模型推理没有可靠取得之前的工具执行事实，可能重复探索或误判文件没有修改。
优先改善这一现有体验，不以新增按钮、完整Task实体、额度追加确认或自动恢复调度为前置。主动停止、Provider异常、进程崩溃、决策停止及现有群聊涉及的不同执行状态，是同一套机制的验收场景，不是新的独立产品阶段。
浏览器刷新或断网仅恢复界面；后端仍在运行时不得因此重新派发操作。用户停止后不自动继续。

## 2. 复用现有事实来源

- AgentExecution、Generation、Message 和 chain_id 关联执行及消息；ExecutionWorkspace 保存工作区租用快照。无需另造业务Trace或解析日志重建状态。
- 消息工具part与加密ToolExecutionDetail通过call_id关联。已有文件提交、版本及目录副作用凭据优先复用，不另复制全部源码或工具参数到“记忆表”。
- 详情有七天保留期，可能缺失、过期或解密失败；这些情况不等于操作未执行。旧记录没有关联身份时不得靠工具名、参数相似或时间猜配。
- 当前stopped正文带停止原因进入历史，error/interrupted正文不进入，工具part只有占位。实现恢复时必须通过核对后的事实投影弥补，不能直接把全部截断回答和未完成工具JSON恢复到模型上下文。

## 3. 操作边界保存证据

在可能产生副作用的执行前保留稳定身份和必要前提；操作完成时及时保存实际结果，不等待模型生成最终回答。批量操作按项保存，前项成功不能被后项失败覆盖。
最小证据包括来源执行/调用/工作区、已开始或确定未派发状态、已确认的提交及版本、已知目录副作用；验证结果保留其适用版本或范围，无法证明关联版本时明确限制。
文件系统与数据库不是同一事务，提交后回执落库前崩溃仍可能产生未知结果。记录未知并在继续前核对，不承诺任意崩溃恰好执行一次，不补造历史成功。
必要证据持久化与展示详情分开：diff省略不应丢提交事实；需要新增持久字段时提供迁移、权限、加密及保留契约，不擅自延长全部私有详情保存时间。

## 4. 关联上下文，不先重建调度系统

保留用户正常发送消息的方式。后续输入进入现有上下文构建流程时，按会话、角色、工作区和可追溯来源选择仍相关的中断执行证据；具体来源选择、失效和交接生命周期已定稿在[内部协议](../../protocol/internal/interruption-context.md)：仅当前用户消息之前、同角色最近的中断回复；最近回复正常结束时不交接。
不能只匹配“继续”两个字就重放工具或强制恢复旧目标。交接是供模型理解的事实数据，不是要求完成旧任务的高优先级命令；用户转向新目标时以当前请求为准。
普通新消息仍保持原有新执行链与预算配置语义。新增恢复来源关联仅用于事实可追溯，不等于复活旧执行、隐式追加旧链额度或重置旧链计数；真正的原链自动续跑不属于当前范围。
新执行与工具使用新身份，旧消息和终态不被改写；网络重发沿用消息幂等机制，不能因为有中断来源而重复启动。
群聊只向当前被授权角色交接其可见且相关的事实，不把其他角色私有工具详情、其他会话或其他World内容无条件混入。跨角色可见性必须由现有资源与详情权限决定，不能靠模型自行判断。

## 5. 核对规则

| 证据与当前状态 | 恢复事实与行为 |
|---|---|
| 提交凭据存在，当前文件匹配最后确认版本 | 告知已经提交且当前仍匹配，不要求重做 |
| 提交凭据存在，但文件后来变化或被删除 | 保留历史成功，明确当前状态变化，按需读取，不套旧hash |
| 明确未派发 | 告知该项未执行；是否再做由当前用户任务和模型重新决策，不重发旧参数 |
| 文件未提交但已创建目录 | 分别表达文件与目录事实 |
| 缺少提交回执，但当前内容符合预期 | 只确认当前内容已存在，不反推历史提交事件，不盲重写 |
| 当前状态无法确定或证据不可用 | 明确未知、过期或核对失败，不能冒充未执行或成功 |

同文件连续修改，以最新确认操作为核对基线；如果后面还有未知修改，不能用更早成功证明当前状态。只扫描相关路径，复用现有扫描、敏感路径、链接、编码和取消规则，不扩大读取权限或强制扫描整个工作区。
扫描和哈希不持有数据库写事务。核对只能描述当时观察，实际编辑仍需执行层版本校验和互斥保护，不承诺对外部进程修改的永久快照。
重新检查用户、会话、角色、绑定和工作区状态；绑定被换到另一根时，不把新目录当作旧执行目标。撤权或删除后不再解密和交接旧私有内容。
Shell、MCP和外部操作无法普遍由文件hash判断结果。保留已知回执和未决风险，先查询可核对的资源；无法核对的副作用不得自动重放。批准不等于执行，退出码0不等于整个任务验收。

## 6. 按需交接，保持正常对话简单

只对相关中断来源生成简短、有界的服务端事实投影，不在每轮回答正文添加摘要，不调用另一个模型做总结。
包含必要的停止原因、已完成修改、版本变化、明确未执行项、未知项及已记录验证事实；区分历史证据与本次观察，不复制完整执行日志或所有旧工具输出。
恢复内容靠近动态上下文尾部，纳入既有输入预算及指纹；不改写稳定系统前缀，也不保证厂商缓存命中。文件和工具内容按不可信数据处理，不提升为系统指令。
超过上下文容量时明确未覆盖范围；不能丢掉重要未知项后仍声称全部核对完成。证据缺失时给出局部、不确定的交接，不借机把用户普通发消息的入口一律封锁。
模型仍可为理解代码而重新读取。目标是避免状态丢失导致的重复写入和错误结论，不是强制零重复读取。

## 7. 同一机制的验收场景

确定性测试覆盖：
- 主动停止、决策停止、Provider失败后，下一条用户消息能得到准确且相关的已提交/未执行/未知事实；正常消息不增加无关摘要。
- 进程在派发前、文件提交后回执前、回执落库后响应前崩溃；重启后不猜测结果、不自动重放，核对当前状态并保留历史边界。
- 批量部分提交、同文件多次修改、目录副作用、diff降级、详情过期或解密失败。
- 文件被外部修改/删除，工作区换绑或停用，角色删除、用户撤权、Owner/Guest和World隔离。
- 群聊角色各自中断与完成，交接不串账、不泄露私有详情；未知Shell/MCP副作用不能冒充未执行。
- 用户说“继续”、带具体修改要求继续或改做新目标；不依赖关键词强制执行旧任务。
- 重复消息、断线重连和取消竞争不启动第二份操作；旧计数、旧终态和当前新消息授权语义保持。

浏览器用真实前后端和fake Provider验证发送→文件操作→停止→输入继续→完成，以及关键权限/失败路径，保留截图。
标准真实 World覆盖开发任务的创建、验证、修改、中断和自然语言继续，保留World、角色、会话、执行证据与厂商用量供人工查看。说明联网与费用，不用临时探针替代；不以少完成工作或一次Token下降宣称普遍收益。

## 8. 范围外

新继续按钮优先、完整Task看板、自动分段、预算提醒、进展评分、任务总时间/Token/费用限制、额度追加弹窗、W3多工作树和长期记忆重构均不纳入本次。
可以按代码依赖分小提交验证，但最终验收围绕统一事实恢复，不再把不同中断现象变成四个独立产品阶段。

实施结果：FileEffect保存原生文件写前/提交后最小证据，旧版执行复用原详情；当前状态核对与动态事实交接不生成可见摘要。窗口不足时降级未知提示，不阻断原本可执行的新请求。群聊不扩大原生文件权限，只交接本角色允许的事实范围。验证见[中断事实验收](../../testing/interruption-context.md)。
